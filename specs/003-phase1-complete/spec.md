# Feature Specification: 阶段 1 补全 — 输入模式、种子日志、历史与档案

**Feature Branch**: `003-phase1-complete`
**Created**: 2026-11-11
**Status**: Implemented — 质量门、GUI 冒烟与 Linux `.deb` 包验证通过（2026-11-11）；D-26 已关闭（ADR-024），Windows NSIS 验证待工具链环境
**Input**: SRS v0.5 9.1 阶段 1 范围；FR-01/FR-02/FR-09/FR-11/FR-12；`specs/002-phase1-meihua-desktop/` 已交付的九色竖切；ADR-022、ADR-023。

## 背景

`specs/002` 只交付了“九色 + 生肖手动输入 → 梅花结果 → 报告/依据阅读”的窄竖切，明确不实现传统数字、随机抽卡、种子日志、历史、档案与设置；而 SRS 9.1 的阶段 1 退出范围包含这些能力。本特性补全阶段 1，不进入阶段 2 焦氏易林或阶段 3 纳甲。

## User Scenarios & Testing

### User Story 1 — 传统数字与辅助模式 (P1)

作为学习者，我可以在九色模式与传统数字模式之间切换；传统数字模式输入两个正整数起卦，结果与既有梅花内核一致，并明确标注 L2 规则层级。

**Independent Test**: 使用 `9 / 16` 传统数字输入完成一次推演，结果应为“天地否、初爻、天雷无妄”，与 `TC-MEIHUA-002` 一致；输入 0 或非法数字必须被拒绝。

**Acceptance Scenarios**:

1. **Given** 传统数字模式，**When** 输入 `U0=9`、`D0=16` 并提交，**Then** 调用既有梅花服务并展示与金标准一致的结果。
2. **Given** 传统数字输入为 0 或非整数，**When** 提交，**Then** 阻止提交并显示字段错误。
3. **Given** 九色模式与生肖模式，**When** 切换辅助象类型，**Then** 九色起卦仍只使用九色与辅助象数字，不引入其他色制。

### User Story 2 — 随机抽卡与种子链 (P1)

作为使用者，我可以点击“随机抽卡”让系统用无偏随机生成九色/生肖，或保持手动选择；每次推演都记录基础种子、抽卡子种子、输入快照摘要与推演种子。

**Independent Test**: 固定模式下相同输入与相同版本重复推演，种子链与结果逐项一致；随机抽卡后保存的输入快照可解释本次结果；分布测试仍通过。

**Acceptance Scenarios**:

1. **Given** 九色模式且未手动选择，**When** 点击随机抽卡并推演，**Then** 抽卡结果来自拒绝采样并写入输入快照。
2. **Given** 固定模式、相同档案/时间/版本，**When** 重复推演，**Then** 抽卡子种子、快照摘要与推演种子一致。
3. **Given** 随机抽卡结果，**When** 查看结果或报告，**Then** 显示本次抽到的颜色/生肖与快照摘要，不宣称仅凭参数可复现摇卦。

### User Story 3 — 历史保存与复盘 (P1)

作为使用者，我可以在本地保存每次梅花推演的非敏感记录，按档案查看历史、打开原记录、按原版本查看报告，并可删除单条记录。

**Independent Test**: 完成两次推演后切换档案，确认只看到当前档案记录；打开一条历史，报告与当时一致；删除后主库不可见。

**Acceptance Scenarios**:

1. **Given** 一次成功推演，**When** 推演完成，**Then** 保存 run、步骤、随机快照摘要、报告 Markdown 与版本集合，不保存生辰或问事原文。
2. **Given** 当前档案有历史，**When** 打开历史列表，**Then** 显示时间、模式、输入方案、本卦/变卦、状态，并可打开详情。
3. **Given** 一条历史记录，**When** 打开复盘，**Then** 使用保存时的报告与版本渲染，不因当前资源升级而重算。
4. **Given** 用户删除一条记录，**When** 查询主库，**Then** 记录及关联步骤/快照不可见，界面提示导出文件与系统备份不受控。
5. **Given** 数据库损坏或迁移失败，**When** 启动，**Then** 提示错误并保留原数据，不静默重建。

### User Story 4 — 档案与设置 (P1)

作为家庭成员，我可以创建、切换、重命名和删除轻量档案；每个档案独立保存历史、设置和偏好。

**Independent Test**: 档案 A 设置 `ZIZHENG` 日界，档案 B 保持 `ZICHU`；切换后设置与历史互不影响。

**Acceptance Scenarios**:

1. **Given** 首次启动，**When** 进入应用，**Then** 自动创建默认档案与默认设置。
2. **Given** 两个档案，**When** 切换当前档案，**Then** 输入偏好、历史列表与日界/时区设置按档案隔离。
3. **Given** 修改日界、时区、默认输入模式，**When** 重启应用，**Then** 偏好保留并从本地数据库加载。
4. **Given** 删除非默认档案，**When** 确认删除，**Then** 该档案历史不可见；默认档案不可删除。

### User Story 5 — 阶段 1 验收 (P1)

作为项目维护者，我可以用一条质量门命令验证阶段 1 补全：Rust 测试、前端测试、资源校验、隐私扫描、报告同源与断链拒绝。

**Independent Test**: 运行 `./scripts/check.sh` 与桌面前端测试；在具备 GTK/WebKit 的环境完成 Tauri 启动冒烟。

**Acceptance Scenarios**:

1. **Given** 完整代码与资源，**When** 运行质量门，**Then** 全部通过。
2. **Given** 新增历史/档案功能，**When** 扫描数据库与导出，**Then** 不出现生辰原始值/派生值、问事原文或 HMAC 密钥。
3. **Given** 删除一条资源，**When** 打开依据链接，**Then** 显示“链接不可用/依据缺失”，不崩溃、不联网。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 提供九色与传统数字两种梅花输入模式，并调用既有 Rust 梅花服务，不在前端复制算法。
- **FR-002**: 传统数字 MUST 接受两个正整数，拒绝 0、空值和非法格式；结果按 `MEIHUA-QIGUA-002` 标注 L2。
- **FR-003**: 九色/生肖 MUST 支持手动选择与随机抽卡；随机 MUST 使用既有 CSPRNG + 拒绝采样，不使用低熵交互值单独作为随机源。
- **FR-004**: 每次推演 MUST 生成并展示基础种子、抽卡子种子、输入快照摘要与推演种子；这些值不得包含生辰或问事原文。
- **FR-005**: 系统 MUST 将每次成功推演保存为本地 run、步骤、随机快照摘要、报告 Markdown 与完整版本集合。
- **FR-006**: 历史查询 MUST 按档案隔离；支持列表、详情、删除；详情按保存时报告渲染，不静默重算。
- **FR-007**: 系统 MUST 支持多档案创建、切换、重命名、删除；默认档案不可删除；每个档案独立设置与历史。
- **FR-008**: 设置 MUST 至少覆盖默认输入模式、辅助象模式、日界、时区、动画开关与隐私脱敏；重启后保留。
- **FR-009**: 所有新命令 MUST 拒绝未知档案、非法模式、非法日界/时区与越界数字，并返回可理解错误。
- **FR-010**: 数据库 schema 变更 MUST 通过版本化迁移执行，升级前备份；失败不得破坏原库。
- **FR-011**: 历史与设置不得保存生辰原始值/派生值、问事原文或 HMAC 密钥；问事 HMAC 仅在后续显式功能启用时保存。
- **FR-012**: 报告窗口、复制与下载 MUST 继续使用同一份 Rust 生成的 Markdown；历史报告同样逐字一致。
- **FR-013**: 桌面应用 MUST 离线运行，所有资源、历史与设置读取均来自本地。
- **FR-014**: 键盘、焦点、标签与错误提示 MUST 可被辅助技术感知。
- **FR-015**: 本特性 MUST NOT 启用焦氏易林、纳甲、择吉、三引擎综合评分或任何正式结论。

### Key Entities

- **推演记录**: run_id、档案、时间、模式、输入方案、种子摘要、结果、步骤、报告与版本。
- **档案**: profile_id、显示名、默认标记、创建时间。
- **设置**: 档案级输入模式、辅助象模式、日界、时区、动画与脱敏偏好。
- **抽卡结果**: 颜色/生肖或传统数字、来源（手动/随机）、快照摘要。

## Success Criteria

- **SC-001**: 传统数字金标准 `TC-MEIHUA-002` 通过，非法数字 100% 被拒绝。
- **SC-002**: 固定模式重复推演的种子链与结果 100% 一致；抽卡分布测试保持通过。
- **SC-003**: 每次成功推演都有历史记录；重启后仍可打开，报告与保存时逐字一致。
- **SC-004**: 两档案的历史与设置互不可见；删除档案后主库不可见。
- **SC-005**: 数据库迁移有备份、可回滚，schema 版本与数据字典一致。
- **SC-006**: 隐私扫描 0 命中；历史、设置、报告不含生辰/问事原文/密钥。
- **SC-007**: 前端测试、Rust workspace 测试与质量门全部通过。
- **SC-008**: 阶段 1 仍显示 `PENDING` 与免责声明，不出现三引擎综合评分。

## Assumptions

- 当前默认档案为单库多档案；档案切换为应用内切换，不引入账号系统。
- 历史保存发生在推演成功后；失败推演不写入主库。
- 问事文本与生辰输入仍不在本特性范围内；后续显式启用时按 HMAC/加密约定扩展。
- 报告使用保存时的 Markdown；历史详情不重新调用当前规则集渲染。
- 完整 Tauri GUI 构建依赖 GTK/WebKit，缺失时以命令层测试和前端测试为准。
