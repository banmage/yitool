# Feature Specification: 阶段 2 — 焦氏易林索引骨架与查询联动

**Feature Branch**: `004-phase2-jiaolin`
**Created**: 2026-11-11
**Status**: Draft — 结构先行；4096 条原文校勘受 D-28/O-06 阻塞，本特性不关闭 JL-01，也不关闭阶段 0
**Input**: SRS v0.5 9.1 阶段 2、FR-03、3.2.2；ARS v0.2 1.10/4；IR v0.1 4；`docs/00-PROJECT-ROADMAP.md` 阶段 2；D-28/D-29

## 背景

阶段 1 已完成梅花单引擎桌面闭环。阶段 2 的目标是焦氏易林：64×64 = 4096 条索引、校勘状态与查询联动。当前 `JL-01` 仍为 `PENDING`，底本、校勘与版权（O-06 / D-28）以及白话提示审核（D-29）尚未关闭，因此本特性**不批量录入或编造 4096 条原文**，而是先交付可校验的索引骨架、`PENDING` 语义、查询联动与后续校勘工作流。

本特性完成后，阶段 2 的结构性退出条件（4096 键完整、`origin==target` 64 条、PENDING 显示正确）可以验收；但 `JL-01` 的正式文本校勘仍是独立的、受 D-28 阻塞的后续里程碑。任何未校勘条目必须继续显示“待校勘”，不得作为正式结论。

## User Scenarios & Testing

### User Story 1 — 4096 键索引骨架 (P1)

作为项目维护者，我可以加载一份覆盖全部有序卦对的焦氏易林索引；每条记录都有明确的校勘状态，未校勘条目不会出现编造原文。

**Why this priority**: 没有完整、稳定的 4096 键骨架，后续校勘数据无法安全增量入库，查询联动也无从验证。

**Independent Test**: 加载 `JL-01` 资源，断言恰好 4096 条、无重复键、64 条 `origin==target`、所有卦 ID 都能映射到 `HEX-01`；所有条目初始为 `PENDING` 且不包含虚构原文。删除一条、重复一条或写入未知卦 ID 时，加载器必须拒绝。

**Acceptance Scenarios**:

1. **Given** 一份完整的 `JL-01` 资源，**When** 加载并校验，**Then** 恰好存在 4096 个唯一有序键，覆盖全部 64×64 组合。
2. **Given** 64 个卦 ID 的集合，**When** 枚举 `origin==target`，**Then** 恰好 64 条，且每条的本卦与之卦相同。
3. **Given** 任意一条 `PENDING` 记录，**When** 查看其字段，**Then** 状态显式为 `PENDING`，原文、版本、白话提示可以为空，但不得填入占位诗句或伪造出处。
4. **Given** 资源中存在重复键、未知卦 ID、缺失组合或非法状态，**When** 加载，**Then** 返回可理解的校验错误，不进入可用状态。
5. **Given** 资源版本与清单不一致，**When** 校验，**Then** 校验失败并提示版本/校验和问题。

---

### User Story 2 — 从梅花结果查询焦氏条目 (P1)

作为使用者，我完成一次梅花推演后，可以直接查看本次“本卦 → 之卦”对应的焦氏易林条目；没有变卦时查看本卦本卦条目，也可以手动指定卦对查询。

**Why this priority**: 查询联动是阶段 2 的核心用户价值；没有它，4096 条索引只是孤立数据。

**Independent Test**: 使用梅花金标准“天地否、初爻、天雷无妄”，查询应解析到 `(QIAN/KUN, QIAN/ZHEN)`；不得回退到反向键、对角条目或其他条目。手动选择非法卦对必须被拒绝。

**Acceptance Scenarios**:

1. **Given** 一次梅花推演结果，**When** 打开焦氏查询，**Then** 本卦与之卦取自该结果，动爻只作为注记，不改变索引。
2. **Given** `origin == target`，**When** 查询，**Then** 返回本卦本卦条目，并提示“无变卦取本卦本卦条目”。
3. **Given** `origin != target`，**When** 查询，**Then** 只返回有序键 `(origin, target)` 对应条目，并显示取辞索引。
4. **Given** 用户手动指定本卦与之卦，**When** 提交，**Then** 仅接受 `HEX-01` 中存在的稳定卦 ID；非法或缺失 ID 返回字段错误。
5. **Given** 查询命中 `PENDING` 条目，**When** 展示，**Then** 显示“待校勘”，不生成替代解释。
6. **Given** 查询键不存在，**When** 展示，**Then** 明确显示“该条待校勘，暂不提供解释”，不静默隐藏、不崩溃、不联网补全。

---

### User Story 3 — 原文、白话与校勘状态分离展示 (P1)

作为使用者，我能区分焦氏原文、版本来源和本系统自写白话提示；未校勘条目不显示确定解读，也不会被包装成吉凶结论。

**Why this priority**: 焦氏易林是古文辞参考，不能与三引擎趋势合成，也不能把 `PENDING` 文本当作正式结果。

**Independent Test**: 使用测试夹具中的一条 `VERIFIED` 条目和一条 `PENDING` 条目：前者逐字显示原文、版本与异文，白话提示标注“本系统白话提示，非原文”；后者显示“待校勘”且不出现确定性白话或吉凶等级。测试夹具不得混入发布资源。

**Acceptance Scenarios**:

1. **Given** `PENDING` 条目，**When** 展示，**Then** 显示“待校勘”；若已有原文，可原样展示，但不得输出确定白话提示。
2. **Given** 缺失条目，**When** 展示，**Then** 显示“该条待校勘，暂不提供解释”。
3. **Given** `VERIFIED` 条目，**When** 展示，**Then** 原文逐字显示，附版本来源、异文与校勘状态；白话提示必须标注“本系统白话提示，非原文”。
4. **Given** 任何焦氏条目，**When** 展示或导出，**Then** 不输出独立吉凶等级、不参与三引擎总分、不使用绝对断语。
5. **Given** 原文包含古典语汇，**When** 执行合规扫描，**Then** 扫描针对系统生成的白话与报告包装文本；原文作为引用保留，不被改写或删减。
6. **Given** 结果页或报告，**When** 展示焦氏内容，**Then** 必须同时包含免责声明与 `PENDING` 状态提示。

### User Story 4 — 增量校勘与版本化 (P2)

作为维护者，我可以在 D-28/O-06 关闭后，按底本逐条把 `PENDING` 升级为 `VERIFIED`，记录版本、来源与异文；历史记录仍按原版本渲染。

**Why this priority**: 4096 条校勘是长期工作，必须支持增量入库且不破坏历史复现。

**Independent Test**: 先保存一条使用 `JL-01-v0.1` 的历史记录，再新增一条 `VERIFIED` 条目并升版为 `JL-01-v0.2`；旧历史仍显示旧版本与 `PENDING`，新查询使用新版本。

**Acceptance Scenarios**:

1. **Given** 一条待升级记录，**When** 标记为 `VERIFIED`，**Then** 必须提供非空原文、底本/版本来源与来源引用；异文可以为空，但必须显式。
2. **Given** 缺少原文、版本或来源的条目，**When** 尝试标记 `VERIFIED`，**Then** 校验失败，保持 `PENDING`。
3. **Given** 任意条目内容或状态变化，**When** 发布资源，**Then** `JL-01` 版本与清单 checksum 同步更新。
4. **Given** 旧历史记录，**When** 打开复盘，**Then** 使用保存时的 `JL-01` 版本渲染，不静默重算。
5. **Given** 人工抽查样例，**When** 完成校勘，**Then** 记录抽查范围、底本页码/条目与结论；未记录抽查的批次不得整体标为 `VERIFIED`。
6. **Given** D-28/O-06 尚未关闭，**When** 发布阶段 2 资源，**Then** 默认全部保持 `PENDING`，不得批量伪造或导入未授权文本。

---

### User Story 5 — 阶段 2 验收入口 (P1)

作为项目维护者，我可以用 CLI 与质量门验证索引完整性、查询联动、PENDING 语义、资源校验和隐私边界。

**Independent Test**: 运行焦氏查询 CLI 与 `verify`，检查 JSON 字段、状态和版本；运行 `./scripts/check.sh`，全部通过。

**Acceptance Scenarios**:

1. **Given** 有效卦对，**When** 运行焦氏查询命令，**Then** 输出包含本卦、之卦、状态、原文、版本、异文、白话提示与资源版本的稳定 JSON。
2. **Given** 篡改资源或清单，**When** 运行 `verify`，**Then** 校验失败并指出资源。
3. **Given** 完整代码与资源，**When** 运行质量门，**Then** 全部通过。
4. **Given** 离线环境，**When** 使用焦氏查询与阅读，**Then** 不发起网络请求。
5. **Given** 历史数据库与导出，**When** 执行隐私扫描，**Then** 不出现生辰原始值/派生值、问事原文或 HMAC 密钥。
6. **Given** 阶段 2 输出，**When** 查看状态，**Then** 仍标注 `PENDING`/“待校勘”，不宣称 `JL-01` 已冻结。

---

### Edge Cases

- 资源恰好 4096 条，但存在重复键或缺失组合。
- 卦 ID 拼写错误、大小写不一致或使用未知卦名。
- `origin == target` 与 `origin != target` 的取辞规则被错误合并。
- 查询失败时回退到反向键、对角条目或最近条目。
- `PENDING` 条目带有原文但没有版本来源。
- `VERIFIED` 条目原文为空、版本为空或来源为空。
- 异文为空、异文与原文相同、异文包含多版本并列。
- 原文含古典语汇，被合规扫描误判为系统断语。
- 资源升级后旧历史记录被静默重算。
- 资源清单 checksum 与文件不一致。
- 桌面端链接指向不存在条目或未校勘条目。
- 手动指定卦对时，用户选择了一个无法由单次动爻得到的有序对（索引仍应可查询，但需标注来源为手动）。
- 同一次推演中焦氏查询失败，不得影响梅花结果本身，也不得合成替代结论。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 为 64 卦使用稳定卦 ID，采用现有 `Hexagram::key()` 约定 `UPPER/LOWER`（如 `QIAN/KUN` 表示天地否）；该 ID 不随资源行序、八宫序或显示名变化。
- **FR-002**: `JL-01` MUST 覆盖全部 64×64 有序卦对，恰好 4096 条，无重复、无缺失；其中 `origin==target` 恰好 64 条。
- **FR-003**: 每条 `JL-01` 记录 MUST 包含 `origin_hex_id`、`target_hex_id`、`text`、`edition`、`collation_status`、`variants`、`plain_note`，并 SHOULD 包含 `origin_name`、`target_name`、`source_ref`、`updated_at` 以便阅读与溯源。
- **FR-004**: `collation_status` MUST 仅为 `VERIFIED` 或 `PENDING`；查询结果可以额外返回 `MISSING` 作为“键不存在”的结果状态，但不得把 `MISSING` 写成资源记录状态。
- **FR-005**: 系统 MUST NOT 为缺失或未校勘条目编造原文、版本、异文或白话；`PENDING` 条目允许原文为空，但状态必须显式。
- **FR-006**: 焦氏引擎 MUST NOT 独立起卦；查询输入来自梅花本卦/变卦或用户手动指定，`yao_note` 仅作注记，不改变索引。
- **FR-007**: 取辞 MUST 遵循 `JIAOLIN-INDEX-001`：`origin == target` 取本卦本卦条目；`origin != target` 取有序键 `(origin, target)`。
- **FR-008**: 系统 MUST NOT 在查询失败时回退到反向键、对角条目、相邻条目或任何替代解释。
- **FR-009**: `PENDING` 条目 MUST 显示“待校勘”；若已有原文可原样展示，但不得输出确定白话提示。
- **FR-010**: 缺失条目 MUST 显示“该条待校勘，暂不提供解释”，并保持界面/报告可用。
- **FR-011**: `VERIFIED` 条目 MUST 逐字展示原文，附版本来源与异文；系统自写白话 MUST 标注“本系统白话提示，非原文”。
- **FR-012**: 焦氏输出 MUST NOT 包含独立吉凶等级、绝对断语或三引擎综合评分，也不得参与趋势合成。
- **FR-013**: 所有焦氏结果页、报告与导出 MUST 包含免责声明，并在 `JL-01` 未冻结时显示 `PENDING`/“待校勘”。
- **FR-014**: 每次焦氏查询 MUST 记录查询来源（`MEIHUA` 或 `MANUAL`）、本卦、之卦、动爻注记、`JL-01` 版本与状态；历史记录按保存时版本渲染，不静默重算。
- **FR-015**: `JL-01` 资源 MUST 在 `resources/manifests/data.manifest.json` 登记 id、版本、状态、来源与 SHA-256；资源变更 MUST 同步升版并重算 checksum。
- **FR-016**: 资源加载器 MUST 拒绝重复键、未知卦 ID、缺失组合、非法状态、空 `VERIFIED` 原文/版本/来源、以及清单不一致。
- **FR-017**: 系统 MUST 提供 CLI 焦氏查询入口，输出稳定 JSON，至少包含本卦、之卦、状态、原文、版本、异文、白话提示、资源版本与查询来源。
- **FR-018**: 桌面端 MUST 提供焦氏易林查看区域，展示取辞索引、校勘状态、原文（若有）、版本、异文与白话提示；未校勘/缺失时显示明确状态。
- **FR-019**: 焦氏条目 MUST 支持稳定只读链接；链接解析失败、条目缺失或未校勘时显示明确状态，不静默隐藏、不联网补全。
- **FR-020**: 系统 MUST 保持离线；焦氏资源、历史与查询全部来自本地，不因焦氏功能引入网络依赖。
- **FR-021**: 焦氏资源、日志、历史与导出 MUST NOT 保存生辰原始值/派生值、问事原文或 HMAC 密钥。
- **FR-022**: 合规扫描 MUST 针对系统生成的白话提示、报告包装与导出文本；焦氏原文作为引用保留，不得因扫描而改写原文。
- **FR-023**: `VERIFIED` 升级 MUST 要求非空原文、底本/版本来源与来源引用；异文可为空但必须显式；未记录人工抽查的批次不得整体标为 `VERIFIED`。
- **FR-024**: 在 D-28/O-06 关闭前，阶段 2 资源 MUST 默认全部为 `PENDING`，不得批量录入未授权或未校勘文本。
- **FR-025**: 焦氏查询失败 MUST NOT 影响同一次梅花推演结果的保存与展示，也不得生成替代结论。

### Non-Functional Requirements

- **NFR-001**: 4096 条索引的本地加载与单次查询 SHOULD 在普通桌面环境下 200 ms 内完成；不得因全量加载阻塞 UI。
- **NFR-002**: 资源文件 SHOULD 保持可读、可 diff 的 JSON 结构，便于逐条校勘与代码审查。
- **NFR-003**: 桌面焦氏区域 MUST 可键盘操作，状态、错误与“待校勘”提示 MUST 可被辅助技术感知。
- **NFR-004**: 资源解析错误 MUST 返回可理解的中文错误，不泄露内部路径以外的敏感信息。

### Key Entities

- **焦氏易林记录 (`JL-01`)**: 本卦 ID、之卦 ID、原文、版本来源、校勘状态、异文、白话提示、来源引用、更新时间。
- **稳定卦 ID**: `UPPER/LOWER` 卦对键，如 `QIAN/KUN`；与 `HEX-01` 的上下卦、卦名一一对应。
- **焦氏查询**: 查询来源、本卦、之卦、动爻注记、命中记录、结果状态、`JL-01` 版本。
- **校勘版本**: 底本/参考注本、版本号、校勘说明、抽查记录、资源 checksum。
- **焦氏链接**: 指向具体有序卦对或资源条目的只读链接，缺失/未校勘时返回明确状态。

## Success Criteria

### Measurable Outcomes

- **SC-001**: `JL-01` 恰好 4096 个唯一有序键，覆盖 64×64；重复、缺失均为 0。
- **SC-002**: `origin==target` 条目恰好 64 条；每条的本卦与之卦 ID 相同。
- **SC-003**: 64 个卦 ID 100% 能映射到 `HEX-01` 的卦名与上下卦；未知 ID 为 0。
- **SC-004**: 金标准查询“天地否 → 天雷无妄”解析为 `(QIAN/KUN, QIAN/ZHEN)`；反向键、对角条目与其他条目均不被误命中。
- **SC-005**: 所有 `PENDING` 与缺失条目 100% 显示“待校勘”，且不出现编造原文或确定白话。
- **SC-006**: `VERIFIED` 测试条目的原文、版本、异文逐字一致；白话提示 100% 标注“本系统白话提示，非原文”。
- **SC-007**: 焦氏输出中独立吉凶等级、三引擎综合评分与绝对断语命中数为 0。
- **SC-008**: 资源清单 checksum 校验通过；篡改、重复、缺失、非法状态与空 `VERIFIED` 字段 100% 被拒绝。
- **SC-009**: 旧历史记录在 `JL-01` 升版后仍按原版本渲染；静默重算次数为 0。
- **SC-010**: 隐私扫描 0 命中；离线环境下焦氏查询与阅读不产生网络请求。
- **SC-011**: `./scripts/check.sh`、Rust 测试、前端测试与 CLI 验收全部通过。
- **SC-012**: 阶段 2 输出仍明确标注 `PENDING`/“待校勘”，不宣称 `JL-01` 已冻结或阶段 0 已关闭。

## Assumptions

- 本特性采用“结构先行、数据后补”策略：先锁 4096 键、稳定卦 ID、状态语义、查询联动与校验工具，再在 D-28/O-06 关闭后逐条校勘。
- 稳定卦 ID 复用现有 `Hexagram::key()` 的 `UPPER/LOWER` 约定；若未来需要改变，必须以新版本记录并保持历史可复现。
- `JL-01` 初始版本可以是全 `PENDING` 骨架；阶段 2 验收不要求 4096 条原文全部校勘完成。
- 测试夹具可以包含少量 `VERIFIED` 条目以验证展示与校验路径，但不得混入发布资源，也不得据此宣称 `JL-01` 已完成校勘。
- D-28（底本/校勘/版权）与 D-29（白话提示审核）未关闭前，不批量录入原文，不把任何未校勘条目标为 `VERIFIED`。
- 焦氏易林不独立起卦、不参与三引擎趋势合成、不输出独立吉凶等级。
- 桌面端可以先以只读查看区域交付；完整古籍阅读器、复制/下载与版本对照仍按后续阶段扩展。
- 现有梅花、历史、档案、设置与资源校验能力作为本特性的依赖，不在本特性内重写。
