# Feature Specification: 阶段 0 — 可信基础与可复现内核

**Feature Branch**: `001-phase0-foundation`

**Created**: 2026-11-03

**Status**: Draft

**Input**: 基于 `docs/` 下 SRS v0.5、ARS v0.2、IR v0.1、CAL v0.2、TDS v0.2，建立阶段 0 的可信基础：决策冻结、历法服务、种子链、规则与数据溯源、隐私边界、金标准测试框架、完整推演报告与依据/附件链接后端，为阶段 1 梅花单引擎闭环提供可验收底座。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 固定模式可复现 (Priority: P1)

作为家庭成员，我在固定模式下用同一组输入、同一组规则/数据/历法版本再次推演时，希望得到逐项相同的结果；我导出快照后，换一次会话重新导入，结果仍然一致。

**Why this priority**: 可复现是复盘、学习对照与隐私承诺的前提；如果同输入不同结果，后续所有引擎与历史功能都不可信。

**Independent Test**: 准备一组无生辰的固定模式输入，连续运行 100 次并跨会话重放导出快照，逐项比对卦象、动爻、日志步骤与版本字段。

**Acceptance Scenarios**:

1. **Given** 固定模式、无生辰、九色输入，**When** 使用相同输入与相同版本运行两次，**Then** 本卦、互卦、变卦、动爻、体用、旺衰与步骤日志逐项相同。
2. **Given** 一次固定模式推演的导出快照，**When** 在新会话中导入并重放，**Then** 结果与原始记录一致，且快照不含生辰与问事原文。
3. **Given** 摇卦模式并保存随机快照，**When** 重放该快照，**Then** 六爻结果一致；系统不宣称仅凭参数可复现。

---

### User Story 2 - 历法结果可信可核 (Priority: P1)

作为使用者，我希望看到的农历日期、节气、年/月/日/时柱、日界与旬空都有明确依据，并能用逐日基准数据核对；跨时区或夏令时时刻不会静默出错。

**Why this priority**: 梅花旺衰、纳甲装卦、择吉与黄历全部依赖历法；历法错一天，后面全错。

**Independent Test**: 用至少一整年逐日基准数据跑 CAL 验收，覆盖立春、节气交接、闰月、23:00 日界、跨时区、夏令时重复/缺失时刻。

**Acceptance Scenarios**:

1. **Given** 基准范围内的任一公历日期，**When** 查询农历、年/月/日/时柱与旬空，**Then** 结果与基准数据一致，且返回 `cal`、`cal_data`、`tzdata` 版本。
2. **Given** 立春前后与节气交接时刻，**When** 查询年柱/月柱，**Then** 年柱按立春切换、月柱按节气切换，不按农历初一切换。
3. **Given** 23:00–00:59 的时刻，**When** 使用 `ZICHU` 或 `ZIZHENG` 日界，**Then** 日柱、时柱、旬空按所选日界计算并在结果中标注。
4. **Given** 闰月日期，**When** 查询农历月序与节气月建，**Then** 两者分别输出且不混用，闰月标记正确。
5. **Given** 夏令时重复或缺失时刻，**When** 查询，**Then** 系统按冻结策略处理并显示歧义提示，不静默选择。
6. **Given** 超出支持范围的日期，**When** 查询，**Then** 返回 `CAL_OUT_OF_RANGE`，不静默截断。

---

### User Story 3 - 规则与数据可溯源 (Priority: P1)

作为学习者，我展开任一推演步骤时，希望看到该步骤用了哪条规则、哪张数据表、哪条典籍出处、属于 L1/L2/L3 哪一层；如果数据缺失或未校核，界面明确显示“待校勘/待冻结”，而不是编造。

**Why this priority**: 易学流派差异大，可溯源是“学习工具”而非“伪权威预测”的核心区别。

**Independent Test**: 抽取梅花、种子、历法各 10 个步骤，检查 `rule_ids[]`、`data_refs[]`、`source_ref`、`rule_level` 是否完整；故意移除一条资源，检查是否显示“待校核”且不生成正式结果。

**Acceptance Scenarios**:

1. **Given** 一次推演，**When** 展开任一步骤，**Then** 显示规则编号、数据表编号、典籍出处、规则层级、公式摘要与版本。
2. **Given** 某条规则/数据标记为 `PENDING`，**When** 运行相关引擎，**Then** 结果标注“规则待校核/待校勘”，不显示为正式结论。
3. **Given** 资源文件 checksum 不匹配，**When** 加载，**Then** 拒绝加载并提示修复，不使用损坏数据。
4. **Given** 一条 L3 自定义规则，**When** 展示，**Then** 显著标注“本系统自定义，非唯一流派”，不得冒充 L1 典籍。

---

### User Story 4 - 隐私边界可验证 (Priority: P1)

作为使用者，我输入生辰或问事文本后，希望系统承诺的“生辰不落盘、问事默认不持久化”能被自动化测试验证；删除记录后，主库中不再可见。

**Why this priority**: 隐私承诺一旦被日志、数据库或导出文件破坏，产品定位与信任即失效。

**Independent Test**: 输入含生辰与问事文本的推演，扫描日志、数据库、导出文件与快照；执行删除与备份清理，检查主库不可见。

**Acceptance Scenarios**:

1. **Given** 用户输入生辰，**When** 推演完成，**Then** 日志、数据库、导出快照中均不含生辰原始值与派生值，仅保留 `bazi_present=true`。
2. **Given** 用户输入问事文本但选择不关联历史，**When** 推演完成，**Then** 原文不落盘，快照中 `question_hmac` 为 `NONE` 或不含原文。
3. **Given** 用户选择关联历史，**When** 保存，**Then** 仅保存本地密钥 HMAC 与 `key_id`，不保存原文与密钥。
4. **Given** 用户在应用内删除记录/档案，**When** 查询主库，**Then** 记录及关联索引不可见；界面提示导出文件与操作系统备份不受控。
5. **Given** 密钥不可用，**When** 打开旧记录，**Then** 提示密钥缺失，不覆盖原数据，不静默重算。

---

### User Story 5 - 金标准一键验收 (Priority: P2)

作为开发者，我希望用一条命令运行全部金标准测试，失败时能直接定位到 `rule_id`、输入、期望值与实际值，而不是靠人工“看起来对”。

**Why this priority**: 阶段 0 的交付物不是功能，而是“可验证的基础”；没有测试框架，后续每个引擎都会重复争论。

**Independent Test**: 在干净环境执行测试入口，覆盖种子链、CAL 逐日基准、梅花九色/传统数字、旬空、隐私扫描、随机分布；故意改错一条规则，测试能报出对应 `rule_id`。

**Acceptance Scenarios**:

1. **Given** 干净环境，**When** 执行金标准测试入口，**Then** 全部用例运行完成并输出通过/失败汇总。
2. **Given** 一条规则被改错，**When** 运行测试，**Then** 失败信息包含 `rule_id`、输入、期望值、实际值与版本。
3. **Given** 隐私扫描，**When** 日志/数据库/导出中出现生辰或问事原文，**Then** 测试失败并指出文件与字段。
4. **Given** 随机分布测试，**When** 抽样足够大，**Then** 九色/生肖抽卡通过卡方检验，六爻分布符合 6=1/8、7=3/8、8=3/8、9=1/8。

---

### User Story 6 - 多档案与设置底座 (Priority: P2)

作为家庭使用者，我希望在同一本地实例中切换不同家庭成员档案，每个档案有独立历史、设置与偏好；切换后不会串数据。

**Why this priority**: 档案隔离是阶段 1 的前置能力；阶段 0 先定义存储与隔离契约，避免后期改表。

**Independent Test**: 创建两个档案，分别保存设置与一条推演记录，切换后检查互不可见；删除一个档案不影响另一个。

**Acceptance Scenarios**:

1. **Given** 两个档案，**When** 在档案 A 保存设置与记录，**Then** 档案 B 不可见。
2. **Given** 档案 A 的生辰输入，**When** 切换到档案 B，**Then** 生辰不跨档案共享，且不落盘。
3. **Given** 删除档案 A，**When** 查询档案 B，**Then** 档案 B 数据完整。

---

### User Story 7 - 完整过程可读、可复制、可下载，依据可点开 (Priority: P1)

作为学习者，我希望在一次推演结束后打开独立窗口，完整看到每一步的规则、数据、出处、公式与输出；我可以把同一份完整过程复制到剪贴板或保存为 `.md` 文件，并且所有规则、依据与附件都能通过链接打开阅读。

**Why this priority**: “完整过程 + 可核依据”是学习工具与黑箱测算的分界线；只有展示、复制、下载同源，且依据链接可解析，用户才能复盘与核对。

**Independent Test**: 生成一次梅花推演报告，比对窗口/复制/下载三处内容的步骤数与文本；遍历全部 `rule_id`、`source_ref`、`data_ref` 与 manifest 资源，确认链接可解析；删除一个资源后确认显示“链接不可用”。

**Acceptance Scenarios**:

1. **Given** 一次完成的梅花推演，**When** 打开完整过程报告，**Then** 展示全部步骤及每步 `rule_ids[]`、`data_refs[]`、`source_ref`、`rule_level`、`formula_summary`、`output`、`status`、版本与免责声明。
2. **Given** 完整过程报告，**When** 复制到剪贴板并下载 `.md`，**Then** 两处文本与报告窗口内容逐字一致，文件为 UTF-8 且可被 Markdown 阅读器打开。
3. **Given** 报告中的规则、出处或附件引用，**When** 点击链接，**Then** 打开只读详情，显示标题、版本、状态、原文/摘要或资源元数据。
4. **Given** 某个规则/出处/资源缺失或 checksum 失败，**When** 生成或点击链接，**Then** 显示“链接不可用/依据缺失/待校核”及引用 ID，不输出断链占位或编造内容。
5. **Given** 历史记录，**When** 重新打开完整过程，**Then** 按原版本字段渲染，不使用当前规则/数据静默重算。

---

### Edge Cases

- 闰月：农历月序取所闰月份并标记 `leap=true`；节气月建不受影响。
- 日界边界：22:59、23:00、23:59、00:00、00:59 在 `ZICHU`/`ZIZHENG` 下的日柱与时柱。
- 夏令时重复时刻：同一本地时刻出现两次时的选择与提示。
- 夏令时缺失时刻：本地时刻不存在时的平移方向与提示。
- 超出支持范围：`1899-12-31`、`2101-01-01` 返回明确错误码。
- 资源缺失/损坏：checksum 失败、文件缺失、版本不兼容。
- 规则/数据未冻结：`PENDING` 条目不生成正式结论。
- 颜色输入越界：`color_id` 不在 `1..=9` 时返回明确校验错误。
- 密钥丢失/轮换：旧记录不可验证时的提示与不覆盖。
- 导出文件：默认脱敏；用户显式选择加密导出原文时的确认与提示。
- 删除：应用内删除、备份清理、彻底删除的范围差异。
- 抽卡动画中断/重复点击：状态一致、可重置。
- 随机源失败：摇卦模式提示并禁止生成；固定模式不受影响。
- 报告步骤为空：拒绝标记“完整”与下载，提示失败原因。
- 剪贴板不可用：提示失败并提供全选文本手动复制。
- 下载取消/无权限：取消无副作用；无权限保留内容并提示更换路径。
- 依据/附件断链：显示引用 ID 与“链接不可用/依据缺失”，不隐藏、不编造。
- 链接路径穿越/外部 URL：拒绝解析并记录安全事件。
- 历史版本资源已升级：按原版本渲染，不重算、不替换依据。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 实现“基础种子 → 抽卡子种子 → 输入快照 → 推演种子 → 子种子”的种子链，且基础种子不含抽卡结果。
- **FR-002**: 系统 MUST 保证固定模式在相同输入与相同版本下逐项可复现，并记录全部版本字段。
- **FR-003**: 系统 MUST 对摇卦模式保存原始随机快照与摘要，并支持凭快照重放。
- **FR-004**: 系统 MUST 为 A/B 统一条件对照提供共同基础种子、共同抽卡子种子与共同随机快照；问事文本差异 MUST NOT 改变共同随机条件。
- **FR-005**: 系统 MUST 为每次推演记录 `srs/ars/ir/cal/rule_set/data/seed_algo/rng/tzdata` 版本。
- **FR-006**: 系统 MUST 提供独立的历法服务接口，覆盖公农历转换、闰月、节气、年/月/日/时柱、日界、时区、夏令时、旬空与黄历基础数据。
- **FR-007**: 历法服务 MUST 显式接收 IANA 时区与 `day_bound`，MUST NOT 依赖系统默认值。
- **FR-008**: 历法服务 MUST 分离 `LUNAR-MONTH-INDEX` 与 `JIEQI-MONTH-BRANCH`，并提供各自的输出与日志字段。
- **FR-009**: 系统 MUST 提供至少一年逐日基准数据，覆盖立春、节气交接、闰月、23:00 日界、跨时区、夏令时重复/缺失时刻。
- **FR-010**: 系统 MUST 实现梅花九色起卦与传统数字起卦两套独立输入/公式/金标准。
- **FR-011**: 系统 MUST 实现互卦、变卦、体用、旺衰，并在每步日志中记录规则与数据来源。
- **FR-012**: 系统 MUST 提供“忌神五行/弱势卦位”的规则出处与输出，或在未冻结前明确标记“待冻结”并阻断方位象意正式结果。
- **FR-013**: 系统 MUST 将规则表、映射表、权重表、解释模板、古籍文本作为只读版本化资源加载，并校验 checksum。
- **FR-014**: 每条规则 MUST 具备唯一 `rule_id`、层级、来源、版本、适用范围与测试样例。
- **FR-015**: 每个推演步骤 MUST 记录 `step_id`、`rule_ids[]`、`data_refs[]`、`source_ref`、`rule_level`、`formula_summary`、`output`。
- **FR-016**: 系统 MUST 实现生辰“仅内存、不序列化、不落盘、不入快照、不写日志”的隐私边界，并提供自动化扫描测试。
- **FR-017**: 系统 MUST 实现问事文本“默认不持久化；关联历史使用本地密钥 HMAC；原文需显式确认并加密保存”。
- **FR-018**: 系统 MUST 提供本地档案、设置、历史记录的存储底座，支持档案隔离、删除、备份/恢复与导出脱敏。
- **FR-019**: 系统 MUST 提供统一的金标准测试入口，覆盖种子链、CAL、梅花、旬空、随机分布、隐私扫描与版本完整性。
- **FR-020**: 系统 MUST 在数据缺失、规则未冻结、版本不兼容、checksum 失败时返回明确状态，MUST NOT 静默回退或编造。
- **FR-021**: 系统 MUST 仅接受九色输入（`color_id ∈ 1..=9`），MUST NOT 保留其他色制的规则版本、只读数据或兼容入口。
- **FR-022**: 系统 MUST 提供性能基准记录能力，记录设备、OS、数据规模、样本量、是否含缓存/初始化。
- **FR-023**: 系统 MUST 提供文档同步机制：规则/数据/接口变更时更新 SRS/ARS/IR/CAL/TDS 对应条目并升版本。
- **FR-024**: 系统 MUST 提供完整推演过程 Markdown 渲染能力；同一份渲染结果 MUST 用于窗口展示、复制到剪贴板与下载 `.md`，包含全部步骤、规则/数据/出处/层级/公式/输出、版本与免责声明；步骤为空或依据断链时 MUST 拒绝生成“完整”报告。
- **FR-025**: 系统 MUST 为每条规则、每个 `source_ref`、每个 `data_ref`、每个 manifest 资源与导出记录提供稳定只读链接；链接 MUST 可解析到详情，路径 MUST 经过白名单与防穿越校验；缺失/未校核/checksum 失败时 MUST 显示明确状态，MUST NOT 隐藏或编造。

### Key Entities

- **Profile（档案）**: 家庭成员标识；隔离历史、设置、偏好；生辰不跨档案共享。
- **Run（推演记录）**: 一次推演的元数据、模式、版本、免责声明与关联步骤。
- **SeedChain（种子链）**: 基础种子、抽卡子种子、输入快照、推演种子、子种子及其派生关系。
- **InputSnapshot（输入快照）**: 非敏感输入与抽卡结果；不含生辰。
- **RandomSnapshot（随机快照）**: 铜钱组合、抽卡结果、随机材料与摘要；摇卦模式可重放。
- **StepLog（步骤日志）**: 步骤编号、规则、数据、出处、层级、公式摘要、输出。
- **RuleRecord（规则记录）**: `rule_id`、层级、条件、结果类型、权重、优先级、来源、版本、测试样例。
- **SourceRecord（典籍出处）**: 书名、版本、卷/篇、原文、释义、校勘状态、版权状态。
- **DataManifest（数据清单）**: 表/文件 ID、名称、版本、checksum、状态、来源。
- **CalResult（历法结果）**: 农历、节气、干支、日界、时区、旬空、版本。
- **BaselineRecord（基准记录）**: 公历时刻、时区、日界、农历、节气、干支、旬空、来源、状态。
- **VersionStamp（版本戳）**: 全系统版本集合，随每次推演记录。
- **ReportDocument（完整过程报告）**: `REPORT-v1`；Markdown 字符串、记录 ID、生成时间、状态、证据数量与 SHA-256；窗口/复制/下载同源。
- **EvidenceLink（依据/附件链接）**: 规则、典籍出处、数据/附件资源的稳定 `yitool://` 链接与文档内锚点；含标题、版本、状态、路径/摘要与断链错误。
- **HmacKey（本地密钥）**: 存于 OS Keychain；含 `key_id`；不写数据库/日志。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100 组固定模式金标准推演连续运行 100 次，结果逐项一致率 100%；导出快照跨会话重放一致率 100%。
- **SC-002**: 至少一整年（含闰月年份）逐日基准数据中，农历、年/月/日/时柱、日界、旬空与基准一致率 100%；节气日期与 HKO 基准一致，秒级时刻作为天文计算值标注（无独立秒级权威基准）。
- **SC-003**: 隐私扫描覆盖日志、数据库、导出文件与随机快照，生辰原始值/派生值、问事原文、HMAC 密钥命中数为 0。
- **SC-004**: 抽查 100 个推演步骤，`rule_id`、`data_ref`、`source_ref`、`rule_level` 完整率 100%。
- **SC-005**: 金标准测试入口一条命令运行完成，全部用例在 2 分钟内结束；任一失败能定位到 `rule_id` 与输入。
- **SC-006**: 对缺失/未冻结数据构造 20 个用例，100% 显示“待校核/待勘”，编造结果为 0。
- **SC-007**: 阶段 0 冻结清单（SRS 9.2 等）关闭率 100%，未关闭项均有明确“延期到阶段 X”的记录。
- **SC-008**: 在基准设备上，种子生成 P95 < 50ms、单引擎推演 P95 < 200ms、一年历法遍历 P95 < 500ms。
- **SC-009**: 九色/生肖抽卡通过卡方检验；六爻分布符合 6=1/8、7=3/8、8=3/8、9=1/8。
- **SC-010**: 全仓库不存在旧色制的数据表、规则版本或 UI 入口；`color_id` 越界（0 或 10）100% 被拒绝。
- **SC-011**: 完整过程报告覆盖 100% 步骤与 100% 步骤字段；窗口/复制/下载三处文本一致率 100%；下载文件 UTF-8/Markdown 打开成功率 100%；空步骤与断链用例 100% 被阻断。
- **SC-012**: 全部 `rule_id`、`source_ref`、`data_ref`、manifest 资源与导出记录链接解析成功率 100%；缺失/checksum 失败/路径穿越/外部 URL 用例 100% 显示明确状态或被拒绝。

## Assumptions

- 阶段 0 以“可验证内核 + 最小存储底座”为目标，不追求完整 UI；UI 主流程属于阶段 1。
- FR-024/FR-025 在阶段 0 交付 Rust 报告渲染、依据/附件链接索引与 CLI 验收；独立窗口、复制按钮、下载对话框与只读阅读器 UI 属于阶段 1，阶段 1 退出条件包含三处内容一致与链接遍历通过。
- 技术栈暂按 TDS 推荐（Tauri 2 + React/TS + Rust + SQLite），最终以 ADR 冻结；核心引擎接口保持技术无关。
- 九色暂按 SRS 推荐映射（赤橙黄绿青蓝紫黑白，黑 8 白 9），最终以 D-01 冻结。
- 日界默认 `ZICHU`，时区默认 `Asia/Shanghai`，支持范围 `1900-01-31`～`2100-12-31`，最终以 D-03/D-12/D-13 冻结。
- 日柱基准优先采用 JDN 连续纪日，并以 1900-01-31 甲辰 / 2000-01-01 戊午交叉校验；最终以 D-04 冻结。
- “忌神五行/弱势卦位”已按 D-11/ADR-011 在 ARS 3.8 增补 `MEIHUA-JISHEN-001`（L3 自定义）；`W-01-v0.2`、`HEX-01-v0.2` 已校核（ADR-017/018），但规则集未整体冻结时整体仍输出“待校核”并阻断方位象意正式结果。
- 基准数据至少覆盖 2025（闰六月）与 2026 两年；最终范围以 D-20 冻结。
- 阶段 0 不实现焦氏 4096 数据校勘、纳甲装卦、择吉权重与古籍全文；这些属于阶段 2–5。
- 项目为单人/家庭自用，无服务端、无账号系统、无网络依赖。
