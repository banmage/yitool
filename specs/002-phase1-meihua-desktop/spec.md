# Feature Specification: 阶段 1 — 梅花单引擎桌面闭环

**Feature Branch**: `002-phase1-meihua-desktop`
**Created**: 2026-11-06
**Status**: In Progress
**Input**: 项目路线图阶段 1；SRS v0.5 FR-13/FR-14；TDS v0.2 报告、依据链接与 UI 契约；ADR-020、ADR-021。

## User Scenarios & Testing

### User Story 1 — 使用九色完成梅花推演 (P1)

作为本地学习者，我可以选择九色与生肖、输入起卦时间并发起梅花推演，查看本卦、互卦、变卦、动爻、体用、旺衰和推演状态；结果同时展示版本与免责声明。

**Independent Test**: 对有效和无效九色/生肖/时间输入分别操作；有效输入展示与 Rust 核心一致的结果，越界输入明确报错，资源损坏时拒绝推演。

**Acceptance Scenarios**:
1. **Given** 校验通过的资源与有效输入，**When** 用户发起推演，**Then** 页面展示完整梅花结构化结果、版本、校核状态与免责声明。
2. **Given** 用户未选择九色/生肖或时间无效，**When** 提交表单，**Then** 阻止提交并显示关联字段错误，不产生结果。
3. **Given** 使用了未冻结规则/数据，**When** 展示结果，**Then** 显著标记“待校核”，不得表述为正式结论。

### User Story 2 — 查看并导出完整过程报告 (P1)

作为学习者，我可以在独立报告视图中阅读完整推演过程，并复制或下载 Markdown；窗口、剪贴板和下载内容来自同一份报告。

**Independent Test**: 完成一次推演，比较报告视图文本、剪贴板文本和下载文件内容；三者须逐字一致，并包含免责声明、步骤、版本与依据链接。

**Acceptance Scenarios**:
1. **Given** 一次成功推演，**When** 打开报告视图，**Then** 可查看结构化推演步骤、摘要、版本和免责声明。
2. **Given** 报告视图已打开，**When** 用户复制或下载报告，**Then** 复制/下载的内容与当前视图所用 Markdown 完全一致。
3. **Given** 复制或下载失败，**When** 浏览器/操作系统拒绝操作，**Then** 显示明确错误并保留可手动选择的报告文本。

### User Story 3 — 只读查看规则、出处与资源依据 (P1)

作为学习者，我可以从推演步骤或报告中打开规则、典籍出处及资源链接，查看其状态与可用摘要；阅读过程不修改资源、不联网、不触发重新推演。

**Independent Test**: 打开每种链接并检查返回详情；传入无效、外部或未知链接必须明确失败，PENDING 状态必须保留。

**Acceptance Scenarios**:
1. **Given** 有效 `yitool://` 依据链接，**When** 用户打开链接，**Then** 展示匹配的类型、稳定 ID、标题、版本、状态和只读字段。
2. **Given** 外部 URL、未知 ID 或断链，**When** 用户打开链接，**Then** 显示“链接不可用/依据缺失”及可理解错误，不尝试网络访问。
3. **Given** 依据状态为 `PENDING`，**When** 打开详情，**Then** 明确展示“待校勘/待校核”。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 提供阶段 1 桌面 UI，以九色模式调用既有梅花服务，不在 UI 中复制算法或硬编码规则表。
- **FR-002**: 系统 MUST 为颜色（1–9）、生肖（1–12）、起卦本地时间、时区及日界提供输入与校验；缺失或无效输入不得触发推演。
- **FR-003**: 系统 MUST 展示本卦、互卦、变卦、动爻、体用、旺衰、忌神/弱势卦位、校核状态、版本与免责声明。
- **FR-004**: 系统 MUST 明确显示 `PENDING`/未冻结状态，不得将其包装为正式结论；阶段 1 只实现梅花单引擎，不得显示三引擎综合评分。
- **FR-005**: 系统 MUST 基于既有报告服务产生一份 Markdown，并使用完全相同的字符串驱动报告视图、剪贴板复制与 `.md` 下载。
- **FR-006**: 报告视图 MUST 提供可访问的独立窗口/对话框体验；关闭和打开报告不得重算推演。
- **FR-007**: 复制或下载报告失败 MUST 显示错误，且报告文本仍可手动选取。
- **FR-008**: 系统 MUST 调用现有依据索引解析 `yitool://rule|source|resource/<id>`，以只读形式展示详情；不得提供任意路径或外部网络访问。
- **FR-009**: 对非法/未知依据链接、checksum 无效资源和 PENDING 条目，系统 MUST 显示结构化错误或明确状态，不得静默忽略或模拟成功。
- **FR-010**: UI 与桌面命令不得持久化生辰或问事原文；本特性不新增历史保存。
- **FR-011**: 键盘可操作、焦点可见、表单具备程序化标签，错误状态通过辅助技术可感知。
- **FR-012**: 应用 MUST 离线运行；启动与推演仅加载本地资源，不发起网络请求。

### Key Entities

- **推演视图模型**: 一次有效梅花结果、CAL 查询结果、完整版本集合及其共享 Markdown 报告。
- **依据详情**: 由稳定 `yitool://` href 解析得到的 RULE/SOURCE/RESOURCE 只读记录。
- **表单输入**: 九色 ID、生肖 ID、本地日期时间、IANA 时区及日界策略；不包括生辰或问事文本。

## Success Criteria

- **SC-001**: 100% 的有效输入调用既有 Rust 梅花服务，且界面本身不重新实现起卦/旺衰公式。
- **SC-002**: 九色和生肖所有边界外输入均被拒绝；有效边界输入可正常完成一次推演。
- **SC-003**: 每次结果均显示免责声明、规则/数据状态和完整版本字段。
- **SC-004**: 报告视图、复制文本与下载文件内容逐字相同；报告不得为空且包含全部步骤和免责声明。
- **SC-005**: 有效依据详情 100% 来自本地索引；外部协议、路径和未知 href 均不能被读取。
- **SC-006**: UI 无可见三引擎综合评分、无生辰/问事输入和持久化。
- **SC-007**: UI 表单、报告对话框与依据阅读器可仅用键盘操作；错误和状态对辅助技术可感知。
- **SC-008**: 桌面 UI 的发布构建可在离线资源条件下完成并启动；推演链路不依赖网络。

## Assumptions

- 阶段 0 的 Rust `app`/`meihua`/`rules` 报告与依据服务是唯一业务逻辑来源。
- 起卦时间采用本地墙钟输入，并显式提交 IANA 时区和 `ZICHU`/`ZIZHENG` 日界；默认 `Asia/Shanghai` 与 `ZICHU`。
- 报告保存通过 WebView 下载机制交由用户选择位置；复制通过系统剪贴板 API。
- “独立报告窗口”允许在 Tauri WebView 内实现为带焦点管理的模态窗口，不要求额外系统窗口。
- 本特性不关闭 JL-01，不启用焦氏易林，不实现历史、档案、摇卦或解释引擎。
