## 0. 修订记录

### 0.1 v0.4 相对 v0.3 的主要变更

1. 建立四文档体系：SRS、ARS、IR、CAL、TDS 职责边界；SRS 引用 ARS/CAL/IR，不展开复杂公式。
2. 梅花易数输入拆分为“九色扩展象数输入（L3，新推演标准）”与“传统数字起卦（L1/L2，学习对照）”；问事文本与生辰扰动明确标 L3。
3. 九色体系作为 v0.4 唯一新推演标准输入；不保留其他色制的规则版本或只读兼容；灰色列为二期可选，不进入 v0.4 标准色集。
4. 修正固定模式抽卡种子循环依赖：拆分为“基础种子 → 抽卡子种子 → 输入快照 → 推演种子”。
5. 明确隐私与复现边界：问事文本默认不持久化或使用本地密钥 HMAC；生辰不参与可长期复现种子；含生辰推演不承诺脱离原始输入复现。
6. A/B 统一条件对照模式定义共用随机快照，不因问事文本不同而派生不同随机条件。
7. 纳甲六爻要求完整干支、六十四卦八宫、旬空、变卦流程与多卦金标准；SRS 只定义行为，公式由 ARS v0.2 冻结。
8. 历法拆分为 `LUNAR_MONTH_INDEX` 与 `JIEQI_MONTH_BRANCH`，引用 CAL v0.1。
9. 择吉改为三层规则模型与统一规则抽象；Q-01 拆分为 `LIUYAO-YONGSHEN-01`、`ZEJI-EVENT-01`、`MEIHUA-INTERPRET-01`。
10. 新增 IR v0.1 引用：推演解释规则独立，不由开发人员临时 if/else。
11. 统一版本号、规则 ID、步骤 ID、数据表 ID、典籍出处 ID 的命名关系。
12. 修正优先级与阶段交付矛盾；性能指标增加测试环境条件。
13. 历史删除改为“应用内删除 + 备份/导出清理说明 + 彻底删除机制”。
14. 家庭共用实例增加轻量本地档案隔离。
15. 六十四卦、纳甲干支、焦氏 4096、择吉权重、黄历数据状态统一标注“待冻结/待校勘”。

## 1. 文档概述

### 1.1 项目定位与合规定位

本系统为个人及家庭成员自用、本地离线优先、纯学习娱乐型易学推演记录工具。系统以传统易学经典为学习依据，提供可视化、步骤化、可溯源的推演过程展示、黄历文化查询、择日文化参考、生活提醒和情绪治愈内容。

系统不对外发布、不提供公网服务、不商用、不提供付费测算、不替代医疗、法律、投资、安全、婚姻等重大决策。所有“趋势、宜忌、方位象意、吉凶参考”输出均为传统易学文化学习与娱乐参考，不构成生活决策唯一依据。

对外名称建议使用“易学学习与推演记录工具（自用）”，避免“决策系统”“预测系统”等误导性名称。

### 1.2 核心设计理念

1. **多体系平行对照：** 梅花易数、焦氏易林、纳甲六爻各自按本体系规则运算，平行展示，不合成单一吉凶结论。
2. **输入模型分离：** 各引擎使用各自起卦输入；九色/生肖不作为纳甲起卦依据。
3. **传统与自定义分层：** 严格区分典籍依据（L1）、工程化解释（L2）、系统自定义类象（L3）。
4. **固定与摇卦分离：** 固定模式保证可复现；摇卦模式保存随机快照，保存后可复现。
5. **规则与程序分离：** 易学规则、映射表、权重表、解释规则配置化。
6. **计算与解释分离：** ARS 负责计算，IR 负责把计算结果转换为有依据的文字解释，SRS 负责展示与验收。
7. **隐私可验证：** 生辰不落盘、不写日志、不入快照；问事文本默认不持久化或使用本地密钥 HMAC。
8. **娱乐、学习、生活提醒分离：** 幸运数、治愈文案与正式推演独立。

### 1.3 文档体系与职责边界

| 文档 | 职责 | 状态 |
|---|---|---|
| **SRS v0.4** | 定义系统做什么、行为边界、输入输出、验收标准 | 本文档 |
| **ARS v0.2** | 定义梅花、焦氏、纳甲、择吉的具体算法、公式、映射表、金标准测试 | 待修订冻结 |
| **IR v0.1** | 定义计算结果如何转换为文化象意、趋势说明、注意事项、冲突解释与措辞等级 | 待新增 |
| **CAL v0.1** | 定义公农历、闰月、节气、年/月/日/时柱、日界、时区、夏令时、逐日基准 | 待新增 |
| **TDS v0.1** | 定义架构、模块、接口、数据结构、技术选型、部署、异常实现 | 暂缓，待前三者冻结后编写 |

依赖关系：

```text
SRS
 ├── ARS  → 易学计算结果
 ├── IR   → 文化解释结果
 ├── CAL  → 历法基础结果
 └── TDS  → 软件实现
```

TDS 不得重新定义易学算法；IR 不得重新计算卦象；ARS 不得输出未标注层级的解释性断语。

### 1.4 核心引用典籍与规则分层

引用典籍包括《周易本经》《周易系辞》《周易说卦传》《梅花易数》《焦氏易林》《卜筮正宗》《增删卜易》《钦定协纪辨方书》《渊海子平》《河图洛书》。

| 层级 | 名称 | 说明 | 日志要求 |
|---|---|---|---|
| **L1** | 典籍依据 | 典籍原文或传统通行规则 | 标注书名、篇目、版本、原文/规则摘要 |
| **L2** | 本系统工程化解释 | 为可计算而对传统规则作出的明确解释 | 标注“本系统解释”，说明与典籍关系 |
| **L3** | 本系统自定义类象/权重/扰动 | 九色象数、月序象数扩展、问事/生辰扰动、权重表 | 必须显著标注“本系统自定义，非唯一流派” |
| **PROVISIONAL** | 尚未校核的临时规则 | 开发占位 | 不得作为正式结果；界面显示“规则待校核” |

禁止将 L3 自定义规则伪装为 L1 典籍原文。九色体系、Q/B 扰动、择吉权重、月序象数均属 L3。

### 1.5 术语与缩略语

| 术语 | 说明 |
|---|---|
| 九色扩展象数输入 | v0.4 新推演标准颜色输入，L3 自定义映射 |
| 传统数字起卦 | 独立学习对照模式，按传统数字起卦规则，L1/L2 |
| 固定推演模式 | 相同规范化输入、相同规则/数据/历法版本必得相同结果 |
| 模拟摇卦模式 | 引入随机快照，保存快照后可复现 |
| 基础种子 | 不依赖抽卡结果的种子材料 |
| 抽卡子种子 | 由基础种子派生，用于产生抽卡结果 |
| 输入快照 | 抽卡结果与非敏感输入构成的快照 |
| 推演种子 | 由基础种子与输入快照摘要派生 |

| 卦变索引 | 焦氏易林本卦×之卦 64×64 查询索引 |

| IR | 推演解释规则，负责计算结果到文字解释的转换 |
| CAL | 历法服务规范 |

## 2. 总体说明

### 2.1 用户与使用场景

1. 单一本地实例支持多个家庭成员轻量档案（profile）。
2. 每个档案独立保存历史、设置、偏好；生辰不跨档案共享。
3. 用户进行一事推演、A/B 对照、吉日文化查询、黄历查询、方位象意提醒、幸运数情绪治愈、历史复盘。
4. 用户可查阅古籍原文，仅静态阅读，不参与自动推演。
5. 用户可导出参数快照用于复现固定模式推演（不含生辰）。
6. 用户可分别配置梅花、焦氏、纳甲输入，系统平行展示结果。

### 2.2 假设与约束

1. 系统默认本地离线运行，核心功能不依赖网络。
2. 系统不采集、不上传个人数据。
3. 生辰八字为可选输入，仅当前推演会话进程内使用；不持久化、不写日志、不入导出快照、不保存派生值、不参与可长期复现的推演种子。
4. 问事文本默认不持久化；如需关联历史，使用本地密钥 HMAC 摘要，不用裸 SHA256；用户可选择本地加密保存原文。
5. 所有推演输出必须附带免责声明。
6. 规则表、权重表、解释规则、文案池、古籍文本均需版本化。
7. 传统规则存在流派差异，系统只采用一套明确规则集，并标注差异说明，不宣称“全网统一”或“唯一正确”。
8. 三引擎结果不合成吉凶总分，只做平行对照与差异解释。
9. 六十四卦数据、纳甲干支、焦氏 4096、择吉权重、黄历数据在冻结前不得发布正式结果。

### 2.3 系统边界与不做事项

1. 不提供医疗诊断、治疗建议、心理诊断。
2. 不提供投资、法律、婚姻、人身安全的确定性判断。
3. 不输出“必然、一定、命中、注定”等绝对断语。
4. 不对推背图进行个人小事推演，推背图仅古籍阅读。
5. 不对外传播、不商用、不付费测算。
6. 不将鼠标幸运数、治愈文案包装为预测功能。
7. 不将三引擎结果简单相加为“综合吉凶分数”。
8. 不将九色/生肖未经规则定义直接用于纳甲六爻起卦。
9. 不承诺含生辰推演可脱离原始输入长期复现。
10. 不承诺应用内删除可清除用户自行导出的文件或操作系统备份。

### 2.4 系统架构

采用五层架构：

1. **交互展示层：** 起卦界面、抽卡动画、推演结果、三栏对照、历史复盘、古籍阅读、设置、档案切换。
2. **业务应用层：** 一事推演、A/B 对照、择吉、黄历查询、方位象意提醒、幸运数、历史管理、档案管理。
3. **推演引擎层：** 梅花易数引擎、焦氏易林卦变辞典引擎、纳甲六爻引擎、择吉规则引擎、IR 解释引擎。
4. **领域模型与规则层：** 卦象模型、干支历法、五行关系、神煞规则、六亲世应、典籍出处、规则配置、解释规则、版本管理。
5. **基础设施层：** 随机数服务、哈希/HMAC、本地数据库、时间服务、数据导入导出、日志、加密与备份。

### 2.5 规则配置与典籍溯源管理

1. 规则数据与算法程序分离，采用配置文件/数据表管理。
2. 统一标识关系：

```text
step_id   = 执行步骤编号，如 MEIHUA-QIGUA-001
rule_id   = 规则编号，如 MEIHUA-QIGUA-001；一步骤涉及多规则时用 rule_ids[]
data_ref  = 数据表编号，如 G-01
source_ref= 典籍出处编号，如 SRC-MEIHUA-001
```

3. 每条规则具有唯一 `rule_id`，关联规则层级、来源、版本、适用范围、测试样例。
4. 典籍条目记录书名、版本、卷数、篇章、原文、现代释义、校勘状态、版权状态。
5. 缺失或待校勘条目必须显示“待校勘”，禁止静默编造。
6. 规则变更必须升版本，并保留历史版本以支持历史复盘。

示例：

```json
{
  "step_id": "MEIHUA-QIGUA-001",
  "rule_ids": ["MEIHUA-QIGUA-001", "MEIHUA-QIGUA-002"],
  "data_refs": ["G-01", "COLOR-NUM-02"],
  "source_ref": "SRC-MEIHUA-001",
  "rule_level": "L2/L3",
  "algorithm_version": "ARS-v0.2"
}
```

## 3. 数据与算法行为规范

> 本章定义行为与边界；详细公式、映射表、测试样例由 ARS v0.2、IR v0.1、CAL v0.1 冻结。未冻结规则不得进入对应引擎正式结果。

### 3.1 颜色输入体系：九色标准与传统数字起卦并存

#### 3.1.1 九色扩展象数输入（v0.4 新推演标准，L3）

九色为系统自定义扩展象数体系，不是传统梅花易数原典标准。采用以下唯一映射（D-01/ADR-002）：

| color_id | 名称 | 五行 | 象数 |
|---:|---|---:|---:|
| 1 | 赤色 | 火 | 1 |
| 2 | 橙色 | 土 | 2 |
| 3 | 黄色 | 土 | 3 |
| 4 | 绿色 | 木 | 4 |
| 5 | 青色 | 木 | 5 |
| 6 | 蓝色 | 水 | 6 |
| 7 | 紫色 | 金 | 7 |
| 8 | 黑色 | 水 | 8 |
| 9 | 白色 | 金 | 9 |

规则：

1. 新推演只使用九色输入，`color_id ∈ 1..=9`。
2. 系统不保留其他色制的规则版本、只读数据、迁移分支或展示入口。
3. 灰色列为二期可选，不进入 v0.4 标准色集。
4. 九色象数参与梅花起卦数字、种子拼接、象意展示；不用于纳甲起卦。
5. 九色映射变更须升版，历史记录不得被重新计算。

#### 3.1.2 传统数字起卦（独立学习对照模式，L1/L2）

1. 用户可手动输入两个起卦数字，按传统数字起卦规则计算上下卦与动爻。
2. 该模式用于学习对照，不参与九色自动起象。
3. 该模式不引入问事文本/生辰扰动，除非用户显式启用“自定义增强”，启用后标注 L3。
4. 金标准样例与九色模式分别维护。

#### 3.1.3 辅助象因子：月令模式与生肖模式

**月令模式：** 使用 `LUNAR_MONTH_INDEX`（农历月序象数）参与梅花自定义起象；使用 `JIEQI_MONTH_BRANCH`（节气月建）参与旺衰、纳甲、择吉。二者不得混用。闰月按所闰月份处理并标注。

**生肖模式：** 十二生肖表 Z-01；地支与五行为 L1/L2，象数 1—12 为系统映射，标 L3。

#### 3.1.4 可选输入因子

1. **生辰八字：** 可选；仅会话内换算四柱；不持久化、不写日志、不入快照、不保存派生值、不参与可长期复现推演种子。
2. **问事文本：** 1—500 字符；默认不持久化；如需关联历史，使用本地密钥 HMAC 摘要；用户可选本地加密保存原文。
3. **推演时间：** 默认当前时刻，可指定；记录时区与日界设置。
4. **事项类型：** 用于纳甲用神、择吉事项规则、IR 解释模板，枚举分别由 `LIUYAO-YONGSHEN-01`、`ZEJI-EVENT-01`、`MEIHUA-INTERPRET-01` 定义。
5. **纳甲起卦输入：** 模拟铜钱或手动六爻，独立于九色/生肖。

### 3.2 三引擎输入模型分离

#### 3.2.1 梅花易数引擎输入

输入包括：九色象数或传统数字、月令/生肖辅助象数、可选问事/生辰扰动、推演时间、节气月建旺衰。  
输出：本卦、互卦、变卦、动爻、体用、五行生克、旺衰、忌神五行、弱势卦位。  
规则：起卦公式、互卦、变卦、体用、旺衰由 ARS v0.2 冻结；九色映射与 Q/B 扰动标 L3；传统数字模式单独标注 L1/L2。

#### 3.2.2 焦氏易林卦变辞典引擎输入

焦氏易林不独立起卦。输入：本卦、之卦、动爻注记、查询来源（梅花结果或用户手动）。  
索引：64×64 = 4096 条。取辞规则：本卦等于之卦取本卦本卦；否则取本卦之变卦；用户可手动指定；缺失显示“待校勘”。  
输出：原文、版本来源、校勘状态、白话提示（本系统自写，不篡改原文）。

#### 3.2.3 纳甲六爻引擎输入

独立起卦，九色/生肖不作为起卦依据。支持：

1. 模拟铜钱摇卦：六次投掷，每次三枚，记录正反组合。
2. 手动六爻输入：逐爻输入 6/7/8/9。
3. 固定模式确定性摇卦：由子种子派生六爻随机比特。
4. 摇卦模式：系统安全随机源生成，保存快照。

装卦流程须完整覆盖：本卦、动爻、变卦、八宫归属与宫五行、内外卦纳甲干支、世应、六亲、六神、旬空、月建、日辰、动变、生克冲合、用神。完整干支表、64 卦八宫表、旬空算法、变卦流程由 ARS v0.2 冻结。

#### 3.2.4 三引擎平行展示

1. 同一次问事会话可触发三引擎，但各引擎输入独立配置。
2. 结果三栏并列，不合成总分。
3. 差异解释由 IR v0.1 规则生成，说明差异来自规则不同、输入不同还是随机快照不同。
4. 三引擎平行对照在阶段 4 交付；阶段 1—3 分别交付单引擎闭环。

### 3.3 种子与随机规范

#### 3.3.1 文本规范化

参与种子的文本使用 UTF-8、Unicode NFC；去除首尾空白，连续空白压缩；空生辰记 `"NONE"`；模式标识 `FIXED` 或 `CAST`；必须包含算法版本、规则版本、数据版本、历法版本。

#### 3.3.2 种子链（消除循环依赖）

```text
base_seed = SHA256(canonical_json({
  algo, mode, profile_id, run_time, rule_set, data_version, cal_version
}))
draw_seed = HMAC(base_seed, "DRAW|" + draw_purpose)
color_id, aux_id = draw(draw_seed)          # 抽卡结果
input_snapshot = {color_id, aux_id, aux_type, question_hmac, bazi_present, ...}
run_seed = HMAC(base_seed, "RUN|" + SHA256(canonical_json(input_snapshot)))
sub_seed(engine, step) = HMAC(run_seed, engine|step|purpose)
```

规则：

1. 基础种子输入不得包含尚未产生的抽卡结果。
2. 固定模式抽卡由 `draw_seed` 确定性派生，抽卡结果写入输入快照。
3. 推演种子由基础种子与输入快照摘要派生。
4. 含生辰时，生辰仅在内存参与；含生辰推演不承诺脱离原始输入长期复现。
5. A/B 统一条件对照模式使用共同 `draw_seed` 与共同随机快照，不因问事文本不同而派生不同随机条件。

#### 3.3.3 固定模式与摇卦模式

1. 固定模式：不引入系统随机熵；相同规范化输入、相同版本必得相同结果。
2. 摇卦模式：使用系统安全随机源生成随机快照，保存快照与生成器版本；最终推演种子由基础种子与快照摘要派生。
3. 不得宣称仅凭参数可复现摇卦结果。

#### 3.3.4 随机生成与拒绝采样

1. 抽卡、六爻摇卦、1—99 幸运数使用系统安全随机源/CSPRNG。
2. 使用拒绝采样避免模偏差。
3. 六爻每爻三枚公平铜钱，理论分布：6 老阴 1/8、7 少阳 3/8、8 少阴 3/8、9 老阳 1/8；不得视为各 25%。
4. 鼠标毫秒时间戳与按压时长为低熵交互扰动，不得单独作为随机熵；幸运数以 CSPRNG 为主。
5. 日志记录随机模式、熵源类型、快照摘要、生成器版本，不记录生辰派生信息。

#### 3.3.5 隐私与复现边界

| 模式 | 数据处理 | 复现能力 |
|---|---|---|
| 普通固定推演（无生辰） | 保存非敏感输入、抽卡结果、规则版本 | 完整复现 |
| 含生辰的临时推演 | 生辰仅内存参与，不落盘 | 不承诺脱离原始输入长期复现；重算需用户重新输入生辰 |
| 模拟摇卦 | 保存铜钱组合与随机快照 | 保存快照后可复现 |
| A/B 统一条件对照 | 保存共同随机快照与各自解释输入 | 可复现对照条件与解释 |

问事文本处理：

1. 默认不持久化。
2. 如需关联历史，使用本地密钥 HMAC 摘要，不用裸 SHA256。
3. 用户可选本地加密保存原文。
4. 导出快照默认不含问事原文。

### 3.4 择吉规则引擎

择吉为独立三层规则引擎：

1. **基础历法层：** 干支、节气月建、日支、生肖冲合、时区、日界。
2. **规则判定层：** 建除、二十八宿、吉神凶神、月破、岁破、四废、大耗等；每条规则统一抽象：

```text
rule_id, event_type, rule_category, condition,
result_type, weight, priority, source_ref, rule_level
```

`result_type`：`POSITIVE | NEGATIVE | ABSOLUTE_FILTER | INFORMATION | CONFLICT`。

3. **事项适配层：** 嫁娶、出行、动工、签约、会客等分别配置 `ZEJI-EVENT-01` 规则集；不得用同一套权重覆盖所有事项。

输出要求：

1. 保留规则命中情况、绝对过滤原因、加减分依据、事项适配情况、冲突规则及解释。
2. 不输出单一“吉日总分”作为唯一结论。
3. 冲突规则保留并解释，不静默覆盖。
4. 周期上限默认 366 天；超过提示分段查询。
5. 权重表 W-02 与事项规则集待冻结。

### 3.5 黄历与历法行为

1. 历法由 CAL v0.1 冻结：公农历转换算法、闰月、24 节气时刻、年柱立春切换、月柱节气切换、日柱纪日基准与日界、时柱划分、IANA 时区、夏令时歧义处理。
2. 拆分 `LUNAR_MONTH_INDEX`（农历月序，供自定义月序起象）与 `JIEQI_MONTH_BRANCH`（节气月建，供旺衰、纳甲、择吉）。二者不得共用一张表。
3. 日界默认“子初换日”，可配置为子正；必须在结果与日志中展示。
4. 黄历输出干支、节气、建除、星宿、冲煞、彭祖百忌、宜忌；宜忌附流派说明与出处。
5. 不宣称“全网统一”，改为“本系统采用《钦定协纪辨方书》规则集及固定数据表版本”。
6. CAL v0.1 冻结前，纳甲、旺衰、择吉、黄历不得宣称计算正确。

### 3.6 推演解释规则 IR

1. 计算结果到文字解释由 IR v0.1 规则完成，不使用开发临时 if/else。
2. IR 输入：卦象、五行关系、体用、旺衰、六亲、世应、神煞等结构化结果。
3. IR 输出：文化象意、趋势说明、变化节点、注意事项、冲突解释、措辞等级。
4. IR 规则须有 `rule_id`、来源、版本、适用范围、测试样例。
5. IR 不得重新计算卦象，不得输出绝对断语。
6. 措辞等级至少区分：`偏顺 | 中性 | 需谨慎 | 信息不足 | 建议观察`。

### 3.7 方位象意提醒

从梅花卦象提取忌神五行、弱势卦位，映射八卦方位、自然物象、环境场景，输出柔性提醒。措辞不得使用“绝对禁忌”“必须避开”。页面内嵌洛书九宫图。提醒不替代气象、交通、安全、医疗判断。

### 3.8 幸运数与情绪治愈

1. 长按鼠标/触摸板至少 300ms 或键盘空格长按触发。
2. 以系统 CSPRNG 为主生成 1—99 幸运数，交互时间与按压时长作为附加扰动。
3. 随机匹配温馨生活提醒或哲理治愈文案。
4. 文案池安全审核，不提供医疗、投资、心理诊断建议。
5. 与易学推演独立，无预测属性。

## 4. 功能需求

优先级与阶段对应见第 9 章。P0 = 当前阶段必须；P1 = 重要；P2 = 扩展。

### 4.1 FR-01 参数输入与抽卡系统

**优先级：** P0（阶段 1）  
**描述：** 用户可配置九色输入、传统数字输入、梅花辅助象、纳甲起卦输入、焦氏查询输入；九色与生肖支持手动/随机抽卡。  
**规则：**

1. 九色/生肖卡片默认统一背面。
2. 随机模式点击任意卡片，使用拒绝采样生成结果，翻转展示，其余置灰锁定。
3. 手动模式直接选择。
4. 支持一键重置。
5. 抽卡结果写入输入快照。
6. 卡片正面显示名称、符号、颜色名，色盲友好。
7. 抽卡与选择器只提供九色，不显示其他色制入口。

**验收：** 抽卡分布通过卡方检验；重置状态一致；历史可查看抽卡结果；固定模式下抽卡结果确定后推演可复现；九色输入与规则版本一致。

### 4.2 FR-02 种子生成与推演日志

**优先级：** P0（阶段 1）  
**描述：** 系统按 3.3 生成基础种子、抽卡子种子、输入快照、推演种子，记录结构化日志。  
**日志字段：** step_id、rule_ids[]、data_refs[]、source_ref、rule_level、引擎、输入摘要、公式摘要、输出、引擎版本、规则版本、数据版本、历法版本、随机生成器版本。  
**验收：** 固定模式同输入同结果 100%；日志不含生辰原始值与派生值；问事原文默认不出现；每条专业步骤可展开依据；导出快照可复现无生辰固定推演。

### 4.3 FR-03 一事专项趋势推演

**优先级：** P0（阶段 1 梅花单引擎；阶段 4 三引擎平行）  
**描述：** 针对单一事项，用户分别配置引擎输入，系统展示结果、现状、变化节点、趋势参考、注意事项。  
**流程：**

1. 录入问事文本（或选择不保存）、事项类型、推演时间。
2. 配置梅花输入：九色或传统数字 + 月令/生肖 + 可选生辰。
3. 配置纳甲输入（阶段 3 起）：模拟铜钱或手动六爻。
4. 焦氏查询（阶段 2 起）：默认使用梅花本卦/变卦，也支持手动指定。
5. 各引擎独立运算。
6. 阶段 4 起三栏并列展示，不合成总分。
7. IR 生成差异解释：差异来自规则、输入还是随机快照。
8. 输出免责声明。

**输出措辞：** 使用 IR 措辞等级，禁止绝对断语。  
**验收：** 引擎结果独立；每步有溯源；结果页含免责声明；固定模式可复现；焦氏索引正确；纳甲不使用九色/生肖起卦。

### 4.4 FR-04 二选一事项对照推演

**优先级：** P1（阶段 4）  
**描述：** 支持 A/B 对照，区分两种模式：

1. **独立推演模式：** A/B 分别起卦，保留各自独立结果，标注参数不同，不得直接比较优劣。
2. **统一条件对照模式：** 固定共同基础种子、共同抽卡子种子、共同随机快照策略与规则版本，对两个方案分别解释。

**规则：**

1. A/B 结果不串引擎。
2. 统一条件对照不得因问事文本不同而派生不同随机条件。
3. 对比小结只列差异、利弊、风险，不强制排名、不判定优劣。
4. 参数不同时提示“参数不可完全比较”。
5. 输出控制变量建议。

**验收：** 两种模式结果不混用；统一条件对照共用随机快照可验证；对比小结无绝对优劣结论；可导出对照快照（不含生辰）。

### 4.5 FR-05 周期内黄道吉日文化筛选

**优先级：** P1（阶段 4）  
**描述：** 按周期与事项类型筛选候选吉日，输出依据。  
**规则：** 见 3.4。  
**验收：** 绝对凶日过滤正确；事项规则与权重表版本可追溯；同分排序稳定；每条结果有神煞明细、规则命中、冲突解释与免责声明；一年周期 P95 < 500ms（测试环境见 6.2）。

### 4.6 FR-06 方位象意提醒

**优先级：** P1（阶段 4）  
**描述：** 从梅花卦象提取忌神五行与弱势卦位，输出柔性方位、场景、时段提醒。  
**验收：** 措辞非绝对；九宫图与五行依据一致；不替代安全判断。

### 4.7 FR-07 标准黄历每日宜忌查询

**优先级：** P1（阶段 4）  
**描述：** 查询指定日期黄历信息，支持回溯。  
**验收：** 与 CAL v0.1 基准样例对照一致；宜忌附流派说明；规则集版本显示。

### 4.8 FR-08 幸运数与情绪治愈

**优先级：** P2（阶段 5）  
**描述：** 长按鼠标/空格生成 1—99 幸运数，匹配生活提醒或治愈文案。  
**验收：** 长按阈值有效；防误触；分布均匀；文案无医疗投资建议；与推演结果无绑定。

### 4.9 FR-09 历史推演记录与复盘

**优先级：** P0（阶段 1 起逐步扩展）  
**描述：** 自动保存推演时间、非敏感参数、各引擎结果、吉日记录、方位建议、随机快照、规则/引擎/数据/历法版本。  
**隐私规则：**

1. 不存储生辰原始值与派生值。
2. 问事文本默认不持久化；如关联，使用本地密钥 HMAC；原文保存需用户显式选择并本地加密。
3. 输入快照排除生辰。
4. 支持应用内删除、本地加密可选、导出脱敏提示。
5. 支持数据库备份与恢复。
6. 删除语义见 4.12。

**复盘：** 用户可添加事后结果与学习心得。  
**验收：** 生辰不落盘扫描通过；无生辰固定模式快照可复现；摇卦模式快照可复现；1000 条内查询 P95 < 1s（测试环境见 6.2）。

### 4.10 FR-10 古籍文库阅读

**优先级：** P2（阶段 5；基础阅读可提前）  
**描述：** 内置《周易》原文、《焦氏易林》文本、推背图等古籍，仅静态阅读。  
**规则：**

1. 区分“推演应用典籍”与“传世谶纬典籍”。
2. 标注版本、来源、校勘、版权状态。
3. 推背图仅阅读，不用于个人小事推演。
4. 不参与自动推演。

**验收：** 每部古籍有版本来源；缺失文本标注待校勘；无版权争议文本才可内置。

### 4.11 FR-11 设置与偏好

**优先级：** P0（阶段 1）  
**描述：** 全局记忆固定/摇卦模式、月令/生肖模式、手动/随机默认、日界设置、时区、隐私脱敏选项、A/B 对照默认模式。  
**验收：** 重启后偏好保留；设置变更写入日志；日界设置影响六爻与黄历计算并明确展示；偏好按档案隔离。

### 4.12 FR-12 本地档案与数据管理

**优先级：** P0（阶段 1）  
**描述：**

1. 支持多个家庭成员轻量档案（profile），无需复杂账号系统。
2. 每个档案独立历史、设置、偏好；生辰不跨档案共享。
3. 档案可切换、重命名、删除。
4. 删除语义：

| 操作 | 效果 |
|---|---|
| 应用内删除记录 | 主数据库不再保留该记录及关联索引 |
| 删除档案 | 主数据库删除该档案数据；提示备份/导出文件不受控 |
| 备份清理 | 提供备份文件保留期限设置与手动清理 |
| 彻底删除 | 提供清理主库、备份、关联导出文件的机制，并明确操作系统级备份不在控制范围 |
| 导出文件 | 应用内删除不控制用户已导出的文件 |

**验收：** 档案隔离有效；删除后主库不可见；备份清理可用；彻底删除提示范围；导出文件提示用户自行管理。

## 5. 交互设计规范

### 5.1 抽卡交互

1. 九色/生肖卡片默认全背面统一图案。
2. 随机模式点击任意卡片后生成结果，翻转展示，其余置灰锁定。

4. 支持一键重置。
5. 卡片正面含名称、符号、颜色名，色盲友好。
6. 防重复点击与动画中断处理。
7. 抽卡池与选择器只提供九色，不提供其他色制入口。

### 5.2 结果展示

1. 默认精简展示最终结论。
2. 折叠面板展开完整推演日志与典籍溯源。
3. 三引擎结果三栏并列（阶段 4 起），清晰对照。

5. 所有结果页固定显示免责声明。
6. 结果页显示引擎版本、规则集版本、数据版本、历法版本、推演模式。

### 5.3 模式切换

全局留存并按档案隔离：

1. 固定推演 / 模拟摇卦；

3. 月令象源 / 生肖象源；
4. 手动选参 / 随机抽卡默认；
5. 日界设置；
6. 隐私脱敏选项；
7. A/B 对照默认模式。

### 5.4 可访问性

1. 键盘可完成抽卡、长按幸运数、展开日志。
2. 色盲友好标识。
3. 动画可关闭。
4. 字体缩放不破坏布局。

## 6. 非功能需求

### 6.1 隐私安全 NFR-PRIV

1. 生辰八字仅当前会话进程内使用；不写入持久化存储、不写日志、不入导出快照、不保存派生值、不参与可长期复现推演种子。
2. 问事文本默认不持久化；关联历史使用本地密钥 HMAC；原文保存需用户显式选择并本地加密。
3. 推演记录不含个人敏感信息。
4. 本地离线优先，核心推演无需联网。
5. 历史记录支持本地加密可选、应用内删除、导出脱敏提示、备份恢复。
6. 提供“生辰不落盘”验证脚本或测试用例。
7. 明确本地运行不等于零隐私风险；设备备份、日志、导出文件需提示。
8. 明确应用内删除不控制用户自行导出的文件与操作系统备份。

### 6.2 性能 NFR-PERF

指标与测试环境同时记录：

| 指标 | 目标 | 测试条件 |
|---|---|---|
| 种子生成 | P95 < 50ms | 含抽卡子种子与输入快照 |
| 单引擎推演 | P95 < 200ms | 不含动画；不含首次历法初始化 |
| 三引擎平行 | P95 < 500ms | 阶段 4；不含 IR 解释渲染 |
| 吉日筛选一年 | P95 < 500ms | 含历法计算与规则打分；不含首次数据加载 |
| 历史查询 | P95 < 1s | 1000 条以内；含索引查询 |

测试记录须注明：设备配置、操作系统、数据库规模、样本量、是否含数据读取、是否含历法初始化。

### 6.3 安全与完整性 NFR-SEC

1. 数据表带校验和与版本号。
2. 导出快照含完整性摘要。
3. 本地存储损坏时可提示重建。
4. 不执行外部不可信脚本。
5. 规则文件与数据文件导入需校验来源与版本。
6. 本地密钥 HMAC 的密钥存储与轮换策略由 TDS 定义。

### 6.4 可维护性 NFR-MAINT

1. 规则表配置化，不散落硬编码。
2. 引擎接口隔离，便于扩展。
3. 日志结构 JSON Schema 化。
4. 规则版本、数据版本、算法版本、历法版本、IR 版本可迁移。
5. 历史推演记录记录完整版本信息，支持旧版本复盘。
6. 九色映射版本升级不重算历史记录。

### 6.5 合规文案 NFR-COPY

1. 所有结果页、导出文件、历史记录头部固定免责声明。
2. 禁止绝对断语。
3. 严格区分科学生活提醒、文化易学推演、情绪治愈内容。
4. 文案池安全审核。
5. IR 措辞等级受合规文案规则约束。

### 6.6 兼容性 NFR-COMPAT

1. 支持主流桌面操作系统或本地浏览器。
2. 不强制联网。
3. 时区与日界设置可配置。
4. 夏令时歧义与不存在时刻由 CAL v0.1 定义处理方式。

## 7. 异常处理与边界条件

| 场景 | 处理 |
|---|---|
| 闰月 | 标注闰月；`LUNAR_MONTH_INDEX` 与 `JIEQI_MONTH_BRANCH` 分别处理；日志记录 |
| 无效日期 | 阻止提交并提示 |
| 夏令时不存在/重复时刻 | 按 CAL v0.1 规则提示并处理 |
| 问事文本超长 | 限制 500 字符，提示截断或修改 |
| 生辰格式错误 | 提示格式，不保存原始值 |
| 数据表缺失/损坏 | 显示“数据不可用”，禁止静默编造 |
| 焦氏易林条目缺失 | 显示“待校勘” |
| 纳甲随机源失败 | 提示并禁止生成摇卦结果；固定模式不受影响 |
| 规则冲突 | 保留冲突说明，由 IR 生成解释，不静默覆盖 |
| 导出失败 | 保留原数据，提示路径权限 |
| 历史库升级失败 | 回滚备份，提示 |
| 天气离线 | 二期功能降级，不影响核心推演 |
| 抽卡动画中断 | 保持状态一致，可重置 |
| 问事文本含敏感信息 | 提示默认不持久化；用户确认是否加密保存原文 |
| 颜色输入越界 | `color_id` 不在 1—9 时返回明确校验错误 |
| 备份清理 | 按保留期限提示；彻底删除时说明操作系统备份不受控 |

## 8. 测试与验收

### 8.1 确定性测试

1. 固定模式金标准用例：同输入、同规则/数据/历法版本结果一致。
2. 摇卦模式：保存快照后复现一致。
3. 子种子隔离：各引擎互不干扰。
4. 九色模式与传统数字模式金标准分别维护。
5. 种子链测试：基础种子→抽卡子种子→输入快照→推演种子无循环依赖。
6. 焦氏 64×64 索引完整性。
7. 纳甲多卦金标准：至少乾、坤、既济、未济、泰、否等，不得只用乾为天。

### 8.2 随机性测试

1. 抽卡分布卡方检验。
2. 六爻每爻分布检验：6=1/8、7=3/8、8=3/8、9=1/8。
3. 1—99 幸运数拒绝采样均匀性测试。

### 8.3 隐私测试

1. 生辰输入后扫描日志、数据库、导出文件，不得出现原始值与派生值。
2. 问事文本默认不落盘验证；HMAC 关联验证。
3. 删除后主库不可见；备份清理机制验证。
4. 导出快照脱敏检查。
5. 档案隔离验证。

### 8.4 规则对照测试

1. CAL v0.1 逐日基准：至少一年，覆盖立春、节气交接、闰月、23:00 日界、跨时区、夏令时。
2. 黄历基准日期样例对照。
3. 吉日绝对凶日过滤样例；规则命中与冲突解释样例。
4. 六十四卦索引完整性；纳甲装卦金标准。
5. 典籍 rule_id / data_ref / source_ref 关联完整性。
6. IR 解释规则样例：同一计算结果在不同措辞等级下的输出一致性。

### 8.5 性能测试

按 6.2 指标测试，记录设备、OS、数据库规模、样本量、是否含初始化。
