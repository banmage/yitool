# ADR-009: 数据库加密方案与阶段落地顺序

- **状态：** 已批准
- **日期：** 2026-11-04
- **关联：** TF-02、D-15、TDS 5.3、ADR-007/008
- **决策人：** 项目所有者
- **生效版本：** 阶段 0 不启用；阶段 1 目标 `DB-v1`（SQLCipher）

## 背景

TDS 5.3 列出三种方案：不加密 + 应用内脱敏、SQLCipher 整库加密、字段级 AES-GCM。阶段 0 需要冻结目标方案与过渡策略，否则存储层无法做长期设计。

阶段 0 数据库的实际内容是：档案、设置、推演元数据、步骤日志、随机快照摘要、HMAC 与 `key_id`。**不保存**生辰、问事原文或密钥本身。此时直接引入 SQLCipher 会增加构建链（OpenSSL/加密库）与跨平台打包复杂度，但不产生新的隐私收益。

## 决策

1. **目标方案：SQLCipher 整库加密**。阶段 1 起，主库使用 SQLCipher；密钥由 OS Keychain 中的主密钥派生，不硬编码、不写数据库、不写日志。
2. **阶段 0 过渡：暂不启用 SQLCipher**。在“数据库不含生辰、问事原文、HMAC 密钥”的前提下，使用应用内脱敏 + OS 账户隔离，并满足：
   - 数据库文件权限遵循最小可用（阶段 1 落地为仅当前用户可读写）；
   - 导出/备份默认脱敏；备份文件继承同等保护；
   - 隐私扫描覆盖数据库、日志、导出。
3. **不采用“仅字段级 AES-GCM”作为唯一方案**：字段级加密可保护原文，但结构、时间、关联与索引仍明文；作为 SQLCipher 之外的补充手段保留。
4. **升级路径：** 阶段 1 启用 SQLCipher 时，先备份旧库，再创建加密新库并复制数据；验证后删除明文库及其 WAL/SHM。迁移失败回滚到明文库。
5. **密钥丢失提示：** 密钥不进入任何备份；密钥丢失时数据不可恢复，设置页必须明确提示。
6. **原文加密：** 用户显式选择保存问事原文时，使用独立字段级密钥加密，不复用 HMAC 密钥或数据库密钥。
7. **验收：** 错误密钥打开数据库必须失败；数据库文件用 `strings`/隐私扫描不得出现原文、生辰、密钥；日志不含密钥。

## 影响

- **文档：** 决策登记册 D-15 关闭；TDS 5.3 状态更新为“已批准（ADR-009）”。
- **代码：** 阶段 0 不新增加密依赖；`store` 保持当前 schema；阶段 1 增加 SQLCipher feature 与密钥派生模块。
- **数据/金标准：** 无金标准变化；阶段 1 迁移需纳入 ADR-008 的备份/回滚流程。
- **隐私/合规：** 阶段 0 的隐私底线仍由“不存敏感明文”保证，而不是依赖数据库加密。

## 验证

- 阶段 0：`yitool privacy-scan` 对数据库、日志、导出 0 命中；检查点见 `specs/001-phase0-foundation/quickstart.md`。
- 阶段 1：新增“错误密钥失败”“明文迁移到加密库”“密钥丢失提示”集成测试；备份文件加密验证。
