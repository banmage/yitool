# ADR-010: 性能基准设备、数据规模与判定口径

- **状态：** 已批准
- **日期：** 2026-11-04
- **关联：** O-17、TF-09、D-18、SRS FR-022
- **决策人：** 项目所有者
- **生效版本：** `PERF-v0.1`

## 背景

阶段 0 已有种子、CAL、梅花、数据库性能冒烟，但未冻结“在哪台设备、多大样本、什么构建模式下算通过”。若不固定，性能数字不可比较，也无法判断回归。

## 决策

1. **构建模式：** 阶段 0 基线使用 `cargo test`（debug）与固定阈值；阶段 1 增加 `--release` 基线，debug 结果不得用于对外承诺。
2. **设备记录：** 每次验收记录 OS、架构、CPU 型号、内存、Rust 版本、SQLite 版本、tzdata 版本。测试输出至少包含 OS/架构；完整设备信息写入验收报告，不硬编码。
3. **数据规模：**
   - 种子：200 次固定模式；
   - 梅花：200 次九色起卦；
   - CAL：2026 年 365 天逐日查询；
   - 历史：单档案 1000 条推演，列表查询 100 次、单条可见性查询 1000 次；
   - 择吉 366 天：阶段 4 引擎落地后补测，阶段 0 不伪造。
4. **判定口径：** 每个场景记录样本量，取 P95；不使用平均值。未预热、未缓存，数据库使用 WAL。
5. **阈值（阶段 0，debug）：**

   | 场景 | P95 阈值 |
   |---|---:|
   | 种子生成 | 50 ms |
   | 单引擎梅花 | 200 ms |
   | 一年 CAL 逐日 | 500 ms |
   | 1000 条历史列表 | 100 ms |
   | 单条历史可见性 | 10 ms |

6. **失败处理：** 超过阈值即测试失败；若确认是设备噪声，记录设备与复测结果后再调整阈值，不得直接放宽。
7. **报告：** `cargo test -p yitool-app --test perf -- --nocapture` 输出场景、P95、阈值、OS/架构与数据规模；验收报告记录完整设备信息。

## 影响

- **文档：** 决策登记册 D-18 关闭；quickstart 性能章节同步。
- **代码：** `crates/app/tests/perf.rs` 增加 1000 条历史列表/查询测试；报告函数保持输出 OS/架构。
- **数据/金标准：** 无规则金标准变化；性能数据作为验收证据留存。
- **隐私/合规：** 性能测试使用虚构档案与时间，不含真实生辰或问事。

## 验证

- `cargo test -p yitool-app --test perf -- --nocapture` 全部通过。
- 输出包含 `history runs=1000`、`history-list-1000`、`history-lookup-1000` 与阈值。
- quickstart 验收记录写入设备、Rust/SQLite/tzdata 版本与 P95 结果。
