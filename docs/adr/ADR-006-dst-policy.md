# ADR-006: 夏令时重复/缺失的默认策略

- **状态：** 已批准
- **日期：** 2026-11-04
- **关联：** D-14、CF-06、CAL 1.3/6.4/8.4、CAL-DST-001
- **决策人：** 项目所有者
- **生效版本：** `CAL-RULE-v0.1`（当时状态；已由 ADR-016 升为 `CAL-RULE-v0.2` / `CAL-v0.2`）

## 背景

CAL 1.3 要求对夏令时歧义“返回明确错误码”，而 CAL 6.4 要求默认取第一次并标注 `dst_ambiguity=true`。两处表述冲突：若默认直接报错，用户无法得到可用的历法结果；若只标记不报错，错误码又失去定义。阶段 0 的 CAL 实现已按“解析并标记”工作，需要冻结该语义。

## 决策

1. **重复时刻（fall back）：** 默认取第一次（较早偏移，通常是夏令时偏移）；`dst.ambiguous=true`，输出实际采用的 `selected_offset`。
2. **不存在时刻（spring forward）：** 默认向后平移 1 小时至有效时刻；`dst.gap=true`，输出平移后的 `solar` 与 `selected_offset`。
3. **默认不报错：** 上述两种情形是“可恢复输入”，默认策略必须返回完整历法结果与标记，不返回 `CAL_DST_AMBIGUOUS`/`CAL_DST_GAP`。
4. **错误码保留：** `CAL_DST_*` 仅用于 strict 模式（未来显式配置）或确实无法解析的情形；strict 模式未启用前，不得用错误码替代默认解析。
5. **界面与历史：** UI 必须提示“该时刻存在夏令时歧义/缺失，系统按 … 规则处理”；历史记录保留原始输入、解析结果、`selected_offset` 与 tzdata 版本，不静默重算。
6. **可配置性：** 重复时刻可配置为取第二次；该配置属于阶段 1 设置项，默认值仍为“较早偏移”。

## 影响

- **文档：** CAL 6.4 增补第 5 条，明确默认解析与错误码的关系；决策登记册 D-14 关闭。
- **代码：** `cal::DstOut` 增加 `selected_offset`；`resolve_local` 维持“较早偏移 / 向后平移 1 小时”。
- **数据/金标准：** `timezone_dst` 测试断言 `2026-03-08 02:30 America/New_York` → `03:30 -04:00`，`2026-11-01 01:30` → 较早偏移 `-04:00`。
- **隐私/合规：** 无变化。

## 验证

- `cargo test -p yitool-cal --test timezone_dst` 通过。
- CLI `cal` 输出包含 `dst.ambiguous`、`dst.gap`、`dst.selected_offset`。
- 历史记录按原 tzdata 版本渲染（阶段 1 接入 UI 后验证）。
