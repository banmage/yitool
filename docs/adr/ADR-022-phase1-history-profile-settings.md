# ADR-022: 阶段 1 历史、档案与设置数据策略

- **状态：** 已批准
- **日期：** 2026-11-11
- **关联：** D-23、D-24、D-25、SRS FR-09/FR-11/FR-12、TDS 5.4、`specs/003-phase1-complete/`
- **决策人：** 项目所有者
- **生效版本：** `DB-v0.3`

## 背景

阶段 1 需要保存非敏感的梅花推演历史、档案与设置，但现有 `DB-v0.2` 只能保存 run 元数据与步骤，未保存报告与结果快照；`run_steps.status` 也只允许 `OK/PENDING/ERROR`，无法保存 `MEIHUA-CORE-v0.2` 已校核的 `VERIFIED` 步骤。若不先固定数据策略，历史复盘会丢失原版本状态，或被迫在展示层重算。

## 决策

1. **单库多档案（D-23）：** 使用一个本地 SQLite 数据库保存多个轻量档案；`profiles.profile_id` 为隔离键。档案切换在应用内完成，不引入账号、网络或跨设备同步。默认档案不可删除；删除非默认档案时级联删除其 run、步骤、快照与报告。
2. **历史保存范围：** 每次成功梅花推演保存：
   - `runs`：run_id、档案、时间、模式、引擎范围、版本集合、`random_snapshot_digest`；
   - `run_steps`：全部结构化步骤；
   - `run_reports`（`DB-v0.3` 新增）：输入方案、结果状态、CAL 结果 JSON、梅花结果 JSON、完整 Markdown；
   - `random_snapshots`：固定/摇卦模式的输入快照摘要与可重放 JSON。
   不保存生辰原始值/派生值、问事原文或 HMAC 密钥。
3. **历史渲染：** 历史详情使用保存时的 `report_markdown` 与版本集合，不调用当前规则集重新渲染；报告窗口/复制/下载仍共用该字符串。
4. **日志轮转（D-24）：** 阶段 1 只使用结构化数据库记录与 stderr；不新增独立日志文件。若后续启用文件日志，默认单文件 10MB × 5，可配置，且隐私白名单优先。
5. **备份与清理（D-25）：** 迁移前自动备份为 `yitool.db.bak-<old>-<timestamp>`；用户可手动备份。默认保留最近 30 天、最多 10 份，超出时提示用户清理；应用内删除不控制用户自行导出的文件与操作系统备份，界面必须提示。
6. **schema 迁移（D-17 延续）：** 升 `DB-v0.3`：
   - 新增 `run_reports`；
   - 重建 `run_steps`，状态允许 `OK/PENDING/ERROR/VERIFIED/FROZEN/DEPRECATED`；
   - 迁移前备份，事务内执行，失败回滚并保留原库。
7. **隐私：** 历史读取与删除必须按 `profile_id` 校验；隐私扫描覆盖数据库、报告与导出。查询失败只返回“不可用/无权限”，不得泄露其他档案存在性。

## 理由

- 保存完整报告与结果快照，才能满足“历史按原版本渲染、不静默重算”。
- `VERIFIED` 是 ADR-021 已批准的状态，数据库必须能如实保存，不能降级为 `OK`。
- 单库多档案与现有 `store` schema 一致，避免阶段 1 引入新存储引擎。

## 影响

- **代码：** `crates/store` 新增 `DB-v0.3` 迁移与查询；`crates/app` 新增历史编排；桌面命令与 UI 接入。
- **数据：** 新库直接建到 `DB-v0.3`；旧库迁移前备份。历史记录不因迁移改变内容。
- **测试：** 增加迁移、备份、档案隔离、历史报告逐字一致、删除级联与隐私扫描测试。
- **文档：** 数据字典数据库 schema 条目升 `DB-v0.3`；决策登记册关闭 D-23/D-24/D-25。

## 验证

- `cargo test -p yitool-store`：迁移、隔离、删除、状态保存。
- `cargo test -p yitool-app`：历史保存/读取、报告稳定性、隐私扫描。
- `cargo test -p yitool-desktop --no-default-features`：命令层历史/档案/设置。
- `./scripts/check.sh` 全绿。
