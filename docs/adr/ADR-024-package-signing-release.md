# ADR-024: 阶段 1 安装包签名与发布流程

- **状态：** 已批准
- **日期：** 2026-11-11
- **关联：** D-26、TDS 9.1 `TDS-DEPLOY-001`、TDS 10 安全与信任边界、`specs/003-phase1-complete/`
- **决策人：** 项目所有者
- **生效版本：** `APP-v0.2`

## 背景

TDS 9.1 要求提供平台安装包，并要求“安装包签名与校验和随发布提供”。本项目定位为个人及家庭自用、本地离线、不对外发布、不商用。引入受信任代码签名证书涉及采购、证书保管、时间戳服务与吊销流程，成本与运维负担明显高于当前自用场景的实际风险。阶段 1 需要先明确：是否签名、产出哪些平台包、如何校验完整性。

## 决策

1. **阶段 1 不启用代码签名。** 安装包定位为“本地部署测试包”，仅用于个人/家庭设备安装验证，不作为对外发行物。
2. **签名推迟。** 若未来确有跨家庭分发需求，必须另行提交 ADR，明确证书类型（自签名/受信任商业证书）、私钥保管、时间戳、吊销与更新流程；在此之前不得声称安装包“已签名”或“可信发布”。
3. **校验和随包提供。** 每次构建安装包后生成 SHA-256 校验和文件（如 `yitool_0.1.0_amd64.deb.sha256`）。校验和只证明文件完整性，不证明来源真实性；文档必须明确这一区别。
4. **阶段 1 验证平台。**
   - Linux amd64 `.deb`：作为阶段 1 的实际验证产物，必须完成构建、包内容检查与解包运行冒烟。
   - Windows x64 NSIS：保留构建配置；在具备 LLVM/LLD、Clang、NSIS 的 Windows 或交叉构建环境完成验证前，不视为已验收产物。
   - macOS：当前无构建环境，不产出、不声明支持。
5. **包内容边界。** 安装包只包含可执行文件、只读 `resources/` 与桌面入口；不得包含用户数据库、档案、历史、报告、生辰、问事原文或密钥。首次启动由应用创建数据目录与默认档案。
6. **离线与更新。** 不启用自动更新、遥测或安装时联网；更新由用户手动安装新包完成。安装包版本必须与 `APP_VERSION` 一致，并随附校验和。
7. **发布措辞。** README、报告与界面不得把未签名测试包描述为正式发行版；JL-01 与阶段 0 未关闭前，安装包仅用于部署验证。

## 理由

- 项目章程与 AGENTS 明确“不对外发布、不商用”，受信任签名在当前威胁模型下收益有限。
- SHA-256 足以发现下载损坏或传输篡改，满足自用场景的完整性校验需求。
- 避免在仓库或构建机引入私钥、证书与签名口令，降低密钥泄露风险。
- 保留 Tauri 的 Windows/macOS 打包配置，未来需要时可在不改变应用架构的前提下补充签名。

## 影响

- **文档：** README 发布说明明确“未签名测试包 + SHA-256”；决策登记册关闭 D-26；路线图与 AGENTS 更新剩余阻塞项。
- **构建：** Linux `.deb` 为阶段 1 验证产物；Windows NSIS 保持实验性，需在 Windows 环境验证。
- **安全：** 不新增签名密钥；校验和文件不得被描述为真实性证明。
- **合规：** 不改变“个人及家庭自用、不对外发布”的定位。

## 验证

- `npm run tauri -- build --bundles deb` 成功产出 `.deb`。
- `dpkg-deb -I` / `dpkg-deb -c` 检查包元数据与内容：包含二进制、`resources/`、桌面入口，不包含用户数据。
- 解包后运行 `usr/bin/yitool-desktop`，确认资源加载、数据库初始化与窗口启动正常。
- `sha256sum` 生成并记录校验和。
- 验证记录见 `docs/reports/PHASE1-DEB-PACKAGE-v0.1.md`。
