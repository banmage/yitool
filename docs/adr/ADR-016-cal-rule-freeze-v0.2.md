# ADR-016: CAL 规则集冻结与版本升级

- **状态：** 已批准
- **日期：** 2026-11-05
- **关联：** CF-01～CF-10、ADR-013/014/015、CAL 0.4/10/附录 B/D、D-03/D-04/D-12/D-13/D-19/D-20/D-41/D-42/D-43
- **决策人：** 项目所有者
- **生效版本：** `CAL-v0.2` / `CAL-RULE-v0.2`

## 背景

ADR-013～015 已分别关闭 CAL 的日界/日柱/范围/时区、数据源/基准/边界容差、tzdata 版本决策，但 CAL 文档仍是 `CAL v0.1（历法冻结草案）`，章节中保留“待冻结/待校核”标记，版本常量与代码 `VersionSet.cal` 仍为 `CAL-v0.1`。若不升版，无法区分“草案”与“已冻结规则集”，历史记录与验收也无法引用稳定版本。

## 决策

1. **版本升级：**
   - 文档：`CAL v0.1` → **`CAL v0.2`（规则冻结版）**；
   - 规则集：`CAL-RULE-v0.1` → **`CAL-RULE-v0.2`**；
   - 代码 `VersionSet.cal` 与所有输出统一为 **`CAL-v0.2`**；
   - 数据版本保持 **`CAL-DATA-v0.2`**。
2. **冻结范围：** CF-01～CF-09 全部关闭（ADR-013～015）；CF-10（黄历基础数据 `HL-01` 与 CAL 接口边界）明确延期阶段 4，不计入本次冻结。
3. **文档处理：**
   - 文件重命名为 `docs/历法服务规范 CAL v0.2.txt`；
   - 删除“待冻结”章节标记，改为已冻结结论与 ADR 引用；
   - 修正 1.2 输出示例（2026-11-03 → 农历 09-25 / 辛巳 / 甲戌旬空申酉）与 8.1 基准示例农历年（2025-12-17）；
   - 6.2 有效日期伪代码简化为“仅 `ZICHU` 且 23:00 后 +1 天”；
   - 8.2 明确回归快照不等于权威基准；8.3 明确秒级节气时刻尚无独立权威基准。
4. **数据表状态：** `LUNAR-MONTH-INDEX`、`JIEQI-MONTH-BRANCH` 随规则冻结记为 `VERIFIED`；`CAL-BASE-2025/2026` 仍为 `PENDING`（派生回归快照）；`CAL-TZDATA` 为 `VERIFIED`（2025b）。
5. **历史兼容：** 历史记录按生成时 `CAL-v0.1`/`CAL-DATA-v0.2` 渲染，不因本次升版静默重算；新记录写 `CAL-v0.2`。若需重算历史，必须生成新记录。
6. **文档引用同步：** SRS v0.4、ARS v0.2、IR v0.1、TDS v0.1 中指向当前 CAL 规范的引用统一改为 `CAL v0.2`；`docs/01-DOC-ANALYSIS.md` 作为 2026-11-03 历史审查报告保留原结论，仅在开头增加历史状态说明，不反向改写 2.4 节等历史判断。

## 影响

- **文档：** CAL 规范升版；README/AGENTS/路线图/数据字典/阶段 0 契约与数据模型同步；新增本 ADR。
- **代码：** `crates/domain/src/version.rs` 默认 `cal = "CAL-v0.2"`；`crates/store` 测试样例同步；`resources/data/rules.json` 的 `SRC-CAL-001` 更新为 v0.2 并记为 `VERIFIED`。
- **数据/金标准：** 不改 CAL 数据文件；重新生成 manifest/checksum；阶段 0 数据模型与实现契约中的版本字符串同步为 `CAL-v0.2`。
- **隐私/合规：** 无变化；CAL 冻结不等于其他规则冻结，纳甲/旺衰/择吉/黄历自身规则未校核时仍须标“待校核”。

## 验证

- `cargo test --workspace` 通过；`yitool cal` 输出 `versions.cal = "CAL-v0.2"`。
- `cargo run -p yitool-cli -- verify --resources resources` 通过。
- 全仓库检索：规范引用不再出现当前 CAL 版本 `CAL-v0.1`；ADR-003/006 的历史记录保留原版本号。
- `./scripts/check.sh` 全绿。
