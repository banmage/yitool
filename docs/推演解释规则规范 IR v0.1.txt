## 0. 总则

### 0.1 文档职责

IR（Interpretation Rules）定义 **ARS 计算结果如何转换为有依据的文字解释**，包括：

1. 文化象意表述；
2. 趋势说明；
3. 变化节点说明；
4. 注意事项；
5. 三引擎差异与冲突解释；
6. 措辞等级；
7. 禁忌措辞与合规过滤；
8. 解释规则的数据结构、版本与测试样例。

IR **不**负责：卦象计算、五行生克计算、六亲世应装卦、历法计算、择吉打分。这些由 ARS v0.2 与 CAL v0.1 完成。IR 只消费 ARS 的结构化输出，不重新计算，不修改计算结论。

### 0.2 与上下游文档的关系

```text
CAL v0.1  → 历法基础结果（干支、节气、日界、时区）
ARS v0.2  → 卦象/五行/六亲/世应/旬空/择吉规则命中结果
IR v0.1   → 将上述结构化结果转换为文化象意、趋势说明、注意事项、冲突解释
SRS v0.4  → 规定解释结果的展示方式、验收与合规要求
TDS v0.1  → 解释规则的存储、加载、渲染实现
```

强制约束：

1. IR 不得重新起卦。
2. IR 不得改变 ARS 输出的吉凶、旺衰、生克、旬空、世应等判定。
3. IR 不得输出绝对断语。
4. IR 不得将 L3 自定义规则伪装为 L1 典籍原文。
5. IR 不得将幸运数、治愈文案与正式推演结果绑定。

### 0.3 解释规则分层

| 层级 | 含义 | 示例 |
|---|---|---|
| **IL1** | 典籍语义依据 | 《梅花易数》体用生克语义；《卜筮正宗》用神旺衰语义 |
| **IL2** | 本系统工程化解释 | 将“体克用”映射为“主方可控、过程有阻力”的标准化表述 |
| **IL3** | 本系统自定义表达模板 | 九色象意文案、生活化场景提示、措辞等级映射 |
| **IPROV** | 待校核解释规则 | 尚未经语义审核的占位解释 |

IL3 与 IPROV 必须显著标注，不得冒充典籍原文语义。

### 0.4 版本与标识

```text
IR_VERSION = "IR-v0.1"
IR_RULE_SET = "IR-RULE-v0.1"
IR_TEMPLATE_SET = "IR-TPL-v0.1"
```

解释规则 ID 格式：

```text
IR-{ENGINE}-{CATEGORY}-{NNN}
```

示例：`IR-MEIHUA-TIYONG-001`、`IR-LIUYAO-YONGSHEN-002`、`IR-CONFLICT-001`、`IR-COMPLIANCE-001`。

每个解释结果必须记录 `ir_rule_ids[]`、`ir_version`、`tone_level`。

### 0.5 解释规则数据结构

```json
{
  "ir_rule_id": "IR-MEIHUA-TIYONG-001",
  "engine": "MEIHUA",
  "category": "TIYONG",
  "rule_level": "IL2",
  "condition": {
    "body_element": "木",
    "use_element": "金",
    "relation": "USE_OVER_BODY"
  },
  "tone_level": "需谨慎",
  "template_id": "TPL-MEIHUA-TIYONG-003",
  "text_template": "当前象意为体卦受制，事态推进中外部压力较明显，宜先稳住基本盘，再观察变化节点。",
  "forbidden_phrases": ["必然失败", "注定不成", "一定破财"],
  "source_ref": "SRC-IR-MEIHUA-001",
  "applicable_event_types": ["GENERAL", "CAREER", "TRAVEL"],
  "version": "IR-RULE-v0.1",
  "status": "VERIFIED|PENDING"
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `condition` | 匹配 ARS 结构化输出的条件；采用键值匹配，不做复杂推断 |
| `tone_level` | 解释措辞等级，见第 2 章 |
| `text_template` | 解释模板；可含占位符，如 `{body_element}` |
| `forbidden_phrases` | 该规则下禁止出现的绝对措辞 |
| `source_ref` | 语义依据编号，关联 `SRC-IR-01` |
| `status` | `VERIFIED` 才可发布；`PENDING` 显示“解释待校核” |

## 1. 输入接口

### 1.1 IR 输入对象 `IR-INPUT-001`

IR 接收 ARS 输出的结构化结果，不接收自然语言。输入对象至少包括：

```json
{
  "run_id": "uuid",
  "engine": "MEIHUA|JIAOLIN|LIUYAO|ZEJI",
  "event_type": "GENERAL|CAREER|TRAVEL|MARRY|...",
  "question_hmac": "hmac或NONE",
  "structured_result": {
    "hexagram": {"name": "...", "upper": "...", "lower": "..."},
    "moving_lines": [4],
    "changed_hexagram": {"name": "..."},
    "body_element": "木",
    "use_element": "金",
    "relation": "USE_OVER_BODY",
    "wangshuai": {"body": "囚", "use": "旺"},
    "liuqin": [],
    "shi_yao": 6,
    "ying_yao": 3,
    "xunkong": ["戌", "亥"],
    "shensha_hits": [],
    "rule_hits": [],
    "conflicts": []
  },
  "version": {
    "ars": "ARS-v0.2",
    "cal": "CAL-v0.1",
    "ir": "IR-v0.1"
  }
}
```

### 1.2 输入约束 `IR-INPUT-002`

1. `structured_result` 必须由 ARS 产生；IR 不得自行推断卦象。
2. `rule_hits` 必须是 `ZEJI-RULE-01` 或对应规则表的命中记录。
3. `conflicts` 由 ARS 或规则引擎提供；IR 不重新判定冲突。
4. 缺失字段时，IR 输出“信息不足”，不得补算。
5. 含 `PENDING` 规则的结果，IR 必须继承“规则待校核”标记。

### 1.3 输出对象 `IR-OUTPUT-001`

```json

}
```

## 2. 措辞等级体系

### 2.1 等级定义 `IR-TONE-001`

| 等级 | 代码 | 适用条件 | 表述倾向 |
|---|---|---|---|
| 偏顺 | `FAVORABLE` | 体用相生、用神旺相、规则命中吉神为主 | “整体偏顺，宜稳步推进” |
| 中性 | `NEUTRAL` | 体用比和、旺衰平衡、吉凶规则相当 | “信息中性，可结合现实判断” |
| 需谨慎 | `CAUTIOUS` | 体受克、用神休囚、凶神规则命中 | “需谨慎，注意外部压力” |
| 信息不足 | `INSUFFICIENT` | 输入缺失、规则待校核、数据缺失 | “当前信息不足，暂不作趋势判断” |
| 建议观察 | `OBSERVE` | 冲突明显、变化节点不确定、多引擎分歧大 | “建议观察，等待更多信息” |

### 2.2 等级判定规则 `IR-TONE-002`

等级判定采用 **规则优先级 + 保守合并**：

1. 任一引擎输出 `INSUFFICIENT` 或含 `PENDING` 关键规则 → 该引擎等级为 `INSUFFICIENT`。
2. 三引擎平行展示时，不合并为单一等级；每个引擎保留自己的 `tone_level`。
3. 冲突解释区域可给出“综合观察建议”，其等级取最保守值：`OBSERVE` 优先于 `CAUTIOUS` 优先于 `NEUTRAL` 优先于 `FAVORABLE`；`INSUFFICIENT` 最高优先。
4. 等级不得被用于生成“综合吉凶分数”。

### 2.3 等级与措辞映射 `IR-TONE-003`

| 等级 | 允许措辞 | 禁止措辞 |
|---|---|---|
| `FAVORABLE` | 偏顺、较顺、宜稳步、可关注 | 必成、一定成功、大吉大利 |
| `NEUTRAL` | 中性、平衡、可结合现实判断 | 无所谓、必然平稳 |
| `CAUTIOUS` | 需谨慎、注意、压力、阻力 | 必败、注定不成、大凶 |
| `INSUFFICIENT` | 信息不足、待补充、暂不判断 | 猜测性结论 |
| `OBSERVE` | 建议观察、等待、再评估 | 强行定论 |

## 3. 梅花易数解释规则 `IR-MEIHUA`

### 3.1 体用关系解释 `IR-MEIHUA-TIYONG-001`

| 条件 | 等级 | 解释模板（IL2） |
|---|---|---|
| 用生体 | FAVORABLE | 外部条件对主方有助力，事态推进相对顺，宜借势稳步推进。 |
| 体用比和 | NEUTRAL | 主客力量相当，事态偏平稳，结果更依赖现实执行。 |
| 体克用 | FAVORABLE/NEUTRAL | 主方可控，过程有阻力但整体可推进；注意节奏。 |
| 体生用 | CAUTIOUS | 主方付出较多，注意消耗与边界，避免过度投入。 |
| 用克体 | CAUTIOUS | 外部压力较明显，宜先稳住基本盘，再观察变化节点。 |

**禁止：** 将“用克体”解释为“必然失败”。

### 3.2 旺衰解释 `IR-MEIHUA-WANGSHUAI-001`

| 条件 | 等级调整 | 解释模板 |
|---|---|---|
| 体旺 | 上调一级 | 主方气势较足，具备推进条件。 |
| 体相 | 保持 | 主方得助，环境相对有利。 |
| 体休 | 保持 | 主方力量一般，宜量力而行。 |
| 体囚 | 下调一级 | 主方受制，宜减少冒进，关注外部变化。 |
| 体死 | 下调一级 | 主方力量较弱，宜先守后动。 |

等级调整不得跨过 `INSUFFICIENT`；最多调整一级。

### 3.3 动爻与变化节点 `IR-MEIHUA-DONGYAO-001`

| 动爻位置 | 变化节点表述 |
|---|---|
| 初爻 | 变化起于基础与起步阶段，关注初始条件。 |
| 二爻 | 变化在内部执行层，关注协作与落实。 |
| 三爻 | 变化在过渡位置，注意进退节奏。 |
| 四爻 | 变化在外部环境，关注外部反馈。 |
| 五爻 | 变化在主导位置，关注关键决策。 |
| 上爻 | 变化在收尾阶段，关注结果与边界。 |

### 3.4 忌神与弱势卦位 `IR-MEIHUA-JISHEN-001`

**输入来源：** 忌神五行与弱势卦位由 ARS 3.8 `MEIHUA-JISHEN-001`（L3 自定义）计算；IR 不重新推导，只负责措辞与合规。忌神不等于危险，弱势卦位不等于禁忌方位。

| 条件 | 输出 |
|---|---|
| 忌神五行 = 木 | 注意与木相关场景、方位、时段；表述为“柔性提醒” |
| 弱势卦位 = 西北 | 输出“西北方位相关场景可多留意”，不写“绝对禁忌” |

禁止使用“必须避开”“绝对不能去”。

### 3.5 九色象意补充 `IR-MEIHUA-COLOR-001`（IL3）

九色象意为本系统自定义表达，不是典籍原文。仅作为辅助文化象意，不改变体用判断。文案须经 `IR-COMPLIANCE-001` 审核。

## 4. 焦氏易林解释规则 `IR-JIAOLIN`

### 4.1 原文与白话分离 `IR-JIAOLIN-TEXT-001`

1. 原文必须原样展示，不改写。
2. 白话提示为本系统自写，标注“本系统白话提示，非原文”。
3. `collation_status == PENDING` 时，白话提示不得作为确定解读。
4. 缺失条目输出“该条待校勘”，不生成替代解释。

### 4.2 取辞与解释 `IR-JIAOLIN-INTERP-001`

| 条件 | 输出 |
|---|---|
| `origin == target` | 展示本卦本卦林辞，提示“无变卦取本卦本卦条目” |
| `origin != target` | 展示本卦之变卦林辞，提示取辞索引 |
| PENDING | 展示原文（若有）并标注“待校勘”，不输出确定白话 |
| 缺失 | “该条待校勘，暂不提供解释” |

### 4.3 焦氏不参与趋势打分 `IR-JIAOLIN-SCOPE-001`

焦氏易林为古文辞参考，不参与三引擎趋势合成，不输出独立吉凶等级；仅提供古典参考视角。

## 5. 纳甲六爻解释规则 `IR-LIUYAO`

### 5.1 用神旺衰 `IR-LIUYAO-YONGSHEN-001`

| 条件 | 等级 | 解释模板 |
|---|---|---|
| 用神旺相 | FAVORABLE | 所问之事的主象较有力，具备推进条件。 |
| 用神休囚 | CAUTIOUS | 主象力量一般，宜稳扎稳打，关注外部条件。 |
| 用神受克 | CAUTIOUS | 主象受制，注意压力来源与时间节点。 |
| 用神空亡 | CAUTIOUS/OBSERVE | 主象暂不实，信息可能未完全显现，建议观察。 |
| 用神伏藏 | OBSERVE | 主象未显，需等待条件成熟。 |

### 5.2 世应关系 `IR-LIUYAO-SHIYING-001`

| 条件 | 解释模板 |
|---|---|
| 世生应 | 主方主动付出，注意投入产出。 |
| 应生世 | 外部对主方有助，可借力。 |
| 世克应 | 主方可控，过程有阻力。 |
| 应克世 | 外部压力较明显，宜先稳住。 |
| 世应比和 | 主客相对平衡，结果依赖执行。 |

### 5.3 旬空解释 `IR-LIUYAO-XUNKONG-001`

1. 仅输出“某爻旬空”，不直接推断“事情不成”。
2. 空亡解释须结合用神、动爻、月建日辰；IR 只做模板匹配，不重新计算。
3. 空亡 + 动爻 + 旺相 → “暂空后实，关注后续变化”。
4. 空亡 + 休囚 + 无动 → “主象暂不实，建议观察”。

### 5.4 六神解释 `IR-LIUYAO-LIUSHEN-001`

六神作为辅助象意，不单独决定吉凶。模板须标注“辅助参考”。

| 六神 | 辅助象意 |
|---|---|
| 青龙 | 偏正向、喜庆、文书类提示 |
| 朱雀 | 口舌、信息、沟通类提示 |
| 勾陈 | 拖延、田土、稳定类提示 |
| 螣蛇 | 反复、惊扰、细节类提示 |
| 白虎 | 压力、急迫、安全类提示 |
| 玄武 | 隐晦、暗昧、信息不明类提示 |

禁止将六神单独解释为“必有灾祸”或“必有大喜”。

### 5.5 变卦解释 `IR-LIUYAO-BIANGUA-001`

1. 变卦解释须同时展示本卦与变卦的六亲关系。
2. 变爻与原爻关联展示；不得只展示变卦而隐藏本卦。
3. 变卦六亲独立计算，解释中标注“变卦六亲”。
4. 伏神等扩展信息在冻结前不输出确定解释。

### 5.6 用神映射缺失 `IR-LIUYAO-YONGSHEN-002`

若 `LIUYAO-YONGSHEN-01` 未冻结或事项类型无映射：

- 输出 `INSUFFICIENT`；
- 提示“用神映射待冻结，暂不提供确定解释”；
- 不得临时猜测用神。

## 6. 择吉解释规则 `IR-ZEJI`

### 6.1 规则命中展示 `IR-ZEJI-HIT-001`

每条候选日期输出：

1. 规则命中列表：`rule_id`、`rule_category`、`result_type`、`weight`、`source_ref`。
2. 绝对过滤原因：命中哪个 `ABSOLUTE_FILTER`。
3. 加减分依据：逐条列出。
4. 事项适配情况：该规则是否适用于当前 `event_type`。
5. 冲突规则及解释。

### 6.2 不输出单一总分 `IR-ZEJI-SCORE-001`

1. 不展示“吉日总分”作为唯一结论。
2. 可展示排序，但排序依据须展开为规则命中明细。
3. 同分排序按日期升序，并在界面说明。
4. 绝对过滤日不进入推荐列表，但可查询过滤原因。

### 6.3 事项适配 `IR-ZEJI-EVENT-001`

不同事项使用不同规则集。解释中必须注明“本解释基于事项类型 X 的规则集 ZEJI-EVENT-01，版本 vX”。

### 6.4 冲突解释 `IR-ZEJI-CONFLICT-001`

当同一日期出现吉凶规则冲突：

1. 保留冲突双方规则记录。
2. 输出“规则冲突说明”，解释冲突来自规则类别不同、事项适配不同还是权重方向相反。
3. 不静默覆盖，不强行合并为单一结论。
4. 可给出“建议结合现实安排”的柔性提示。

## 8. 三引擎差异与冲突解释 `IR-CONFLICT`

### 8.1 差异来源分类 `IR-CONFLICT-001`

| 差异来源 | 代码 | 说明 |
|---|---|---|
| 规则体系不同 | `RULE_SYSTEM` | 梅花、焦氏、纳甲本属不同体系 |
| 输入不同 | `INPUT_DIFF` | 各引擎输入独立配置，参数不同 |
| 随机快照不同 | `RANDOM_DIFF` | 摇卦模式快照不同 |
| 数据待校核 | `PENDING_DATA` | 某引擎规则/数据未冻结 |
| 解释模板不同 | `TEMPLATE_DIFF` | 同一计算结果不同模板表达差异 |

### 8.2 冲突解释模板 `IR-CONFLICT-002`

输出结构：

```json
{
  "engines": ["MEIHUA", "LIUYAO"],
  "tone_levels": {"MEIHUA": "需谨慎", "LIUYAO": "中性"},
  "difference_sources": ["RULE_SYSTEM", "INPUT_DIFF"],
  "explanation": "两套体系结论不同，主要来自规则体系差异与输入配置不同；本系统不将二者合并为单一吉凶结论。",
  "suggestion": "建议分别阅读两套体系的依据，结合现实信息自行判断。"
}
```

### 8.3 禁止综合打分 `IR-CONFLICT-003`

1. 不得将三引擎结果相加、加权平均或映射为统一分数。
2. 不得输出“综合大吉”“综合大凶”。
3. 可输出“综合观察建议”，等级取最保守值，且须说明这是展示层建议，不是易学结论。

## 9. 合规文案规则 `IR-COMPLIANCE`

### 9.1 禁用措辞 `IR-COMPLIANCE-001`

以下措辞在解释输出中禁止出现：

```text
必然、一定、注定、命中、必死、必败、大凶、必成、包治、改命、
化解灾祸、保证发财、保证升职、绝对安全、绝对禁忌、必须避开
```

### 9.2 必备声明 `IR-COMPLIANCE-002`

每个解释结果页、导出文件、历史记录头部固定显示：

> 本结果为传统易学文化学习与娱乐参考，不构成生活决策唯一依据，不替代医疗、法律、投资、安全、婚姻等专业判断。

### 9.3 内容分区 `IR-COMPLIANCE-003`

严格区分：

1. 科学生活提醒（如驾驶安全、用电安全）；
2. 文化易学推演（卦象、五行、六亲、神煞）；
3. 情绪治愈内容（幸运数、治愈文案）。

三类内容不得混排为同一结论。

### 9.4 文案审核 `IR-COMPLIANCE-004`

1. 所有 IL3 模板与文案池须经安全审核。
2. 不得提供医疗、投资、心理诊断建议。
3. 文案变更须升版本并保留旧版本。

### 10.2 旧记录复现 `IR-VERSION-002`

2. 用户可手动“按当前版本重新解释”，但须标注“重新解释，非原始记录”。
3. 规则升级不得静默改变历史解释。

## 11. 测试与验收

### 11.1 解释规则匹配 `TC-IR-001`

对每个 `IR-MEIHUA-TIYONG-001` 条件，构造 ARS 结构化输入，验证：

- 命中正确模板；
- `tone_level` 正确；
- 无禁用措辞；
- `ir_rule_ids` 记录正确。

### 11.2 禁用措辞扫描 `TC-IR-002`

### 11.3 冲突解释 `TC-IR-003`

构造梅花“需谨慎”、纳甲“中性”的输入，验证：

- 输出 `IR-CONFLICT-002` 结构；
- 不合并为单一分数；
- 差异来源分类正确。

### 11.4 信息不足 `TC-IR-004`

构造缺失用神映射、焦氏 PENDING、历法未冻结输入，验证：

- 输出 `INSUFFICIENT`；
- 不生成确定解释；
- 显示“待校核/信息不足”。

### 11.5 旧版本复现 `TC-IR-005`

用旧 `ir_version` 记录，验证历史解释不被新模板改写。

### 11.6 合规声明 `TC-IR-006`

所有结果页、导出文件、历史记录头部均包含免责声明。
