## 0. 修订说明与总则

### 0.1 v0.2 相对 v0.1 的主要修正

1. **修正梅花起卦输入矛盾：** 九色模式 `C ∈ 1..9`；传统数字起卦独立为另一输入模式，起卦数字可为正整数。
2. **九色标准化：** 确立 `COLOR-NUM-02` 九色表为唯一颜色输入标准；不保留其他色制表或只读兼容。
3. **传统数字起卦独立：** 九色起象与传统数字起卦分别定义公式、输入接口和金标准样例。
4. **Q/B 扰动标 L3：** 问事文本扰动、生辰扰动明确为本系统自定义增强，不冒充传统梅花规则；默认关闭，用户显式启用。
5. **种子链消除循环依赖：** 拆分为“基础种子 → 抽卡子种子 → 输入快照 → 推演种子 → 子种子”。
6. **隐私与复现边界：** 问事文本默认不持久化；关联历史使用本地密钥 HMAC；生辰不落盘、不入快照、不参与可长期复现推演种子。
7. **A/B 统一条件对照：** 定义共同基础种子、共同抽卡子种子、共同随机快照，不因问事文本不同而派生不同随机条件。
8. **纳甲完整化：** 补齐纳甲干支表、六十四卦八宫表、旬空算法、变卦流程、六亲/六神/世应规则、多卦金标准要求。
9. **历法拆分引用 CAL：** `LUNAR_MONTH_INDEX` 与 `JIEQI_MONTH_BRANCH` 分离；详细历法由 CAL v0.2 冻结，ARS 只定义接口。
10. **择吉规则统一抽象：** 建除、神煞、过滤、评分统一为规则记录；不输出单一总分；冲突保留并解释。
11. **版本/ID 统一：** 统一 `step_id`、`rule_id`、`data_ref`、`source_ref`；统一枚举 `COIN_CAST`、`MANUAL_YAO`、`FIXED_DERIVED`。
12. **金标准重做：** 九色模式、传统数字模式、纳甲多卦、种子链、随机分布、隐私扫描分别建立样例。
13. **忌神算法补充（2026-11-04）：** 增补 `MEIHUA-JISHEN-001`，以克体五行为忌神、同五行卦位为弱势方位；标 L3 自定义，服务 IR 方位象意。

### 0.2 规则层级

| 层级 | 含义 | 处理要求 |
|---|---|---|
| **L1** | 典籍原文或传统通行规则 | 标注书名、篇目、版本；原文不得改写 |
| **L2** | 本系统工程化解释 | 注明“本系统解释”；说明与 L1 关系 |
| **L3** | 本系统自定义类象/权重/扰动 | 显著标注“本系统自定义，非唯一流派” |
| **PROVISIONAL** | 尚未校核的临时规则 | 不得作为正式结果；界面显示“规则待校核” |


## 2. 种子与随机算法

### 2.1 文本规范化 `SEED-NORM-001`

```python
def normalize_text(s: str) -> str:
    s = unicodedata.normalize("NFC", s)
    s = s.strip()
    s = re.sub(r"\s+", " ", s)
    return s
```

- 空生辰统一记 `"NONE"`。
- 问事文本默认不持久化；如需关联历史，使用本地密钥 HMAC：

```text
question_hmac = HMAC-SHA256(local_hmac_key, normalize_text(question))
```

不使用裸 SHA256 作为可持久化匿名标识。

### 2.2 基础种子 `SEED-BASE-001`

基础种子输入**不得包含尚未产生的抽卡结果**：

```json
{
  "algo": "SEED-v2",
  "mode": "FIXED|CAST",
  "profile_id": "string",
  "run_time": "ISO8601",
  "timezone": "IANA",
  "day_bound": "ZICHU|ZIZHENG",
  "rule_set": "RULE-v0.2",
  "data_version": "DATA-v0.2",
  "cal_version": "CAL-v0.2"
}
```

```text
base_seed = SHA256(UTF8(canonical_json))
```

`canonical_json`：键顺序按定义，`ensure_ascii=False`，分隔符 `(",", ":")`。

### 2.3 抽卡子种子 `SEED-DRAW-001`

```text
draw_seed = HMAC-SHA256(base_seed, "DRAW|" + draw_purpose)
color_id, aux_id = draw_with_rejection(draw_seed)
```

固定模式抽卡由 `draw_seed` 确定性派生；抽卡结果写入输入快照。摇卦模式抽卡使用系统安全随机源并写入随机快照。

### 2.4 输入快照与推演种子 `SEED-RUN-001`

```json
input_snapshot = {
  "color_scheme": "NINE_COLOR|TRADITIONAL_NUMBER",
  "color_id": 1,
  "aux_type": "ZODIAC|MONTH",
  "aux_id": 3,
  "traditional_numbers": null,
  "question_hmac": "hmac或NONE",
  "bazi_present": false,
  "liuyao_input_type": "COIN_CAST|MANUAL_YAO|FIXED_DERIVED",
  "random_snapshot_digest": "hex或null"
}
```

```text
snapshot_digest = SHA256(canonical_json(input_snapshot))
run_seed = HMAC-SHA256(base_seed, "RUN|" + snapshot_digest)
sub_seed(engine, step) = HMAC-SHA256(run_seed, engine + "|" + step + "|" + purpose)
```

规则：

1. 无生辰时，`run_seed` 可由基础种子与输入快照复现。
2. 含生辰时，生辰材料仅在内存参与 `run_seed`，不写入快照；该次推演不承诺脱离原始生辰输入长期复现。
3. `question_hmac` 仅用于历史关联；若用户不保存问事关联，则记 `"NONE"`。
4. 日志记录 `snapshot_digest`，不记录生辰材料。

### 2.5 A/B 统一条件对照种子 `SEED-AB-001`

统一条件对照模式：

```text
ab_base_seed = SHA256(canonical_json({algo, mode, profile_id, run_time, rule_set, data_version, cal_version}))
ab_draw_seed = HMAC(ab_base_seed, "AB_DRAW")
shared_random_snapshot = generate_snapshot(ab_draw_seed)
common_snapshot_digest = digest(input_snapshot 去掉 question_hmac/bazi 后)
A_run_seed = B_run_seed = HMAC(ab_base_seed, "AB|" + common_snapshot_digest)
```

A/B 共用抽卡与摇卦随机条件；问事 HMAC、生辰材料与 `A/B` 标签不得进入 `run_seed` 的随机派生。问事文本只影响各自解释上下文与历史关联，不改变共同随机快照。独立推演模式则各自使用普通种子链。该语义由 ADR-004 冻结。

### 2.6 固定模式与摇卦模式 `SEED-FIXED-001` / `SEED-CAST-001`

- 固定模式：不引入系统随机熵；所有“随机”步骤由子种子确定性派生。
- 摇卦模式：使用系统安全随机源生成随机快照；`random_snapshot_digest` 写入输入快照；保存快照后可复现。
- 不得宣称仅凭参数可复现摇卦结果。

### 2.7 拒绝采样 `RNG-REJECT-001`

```python
def uniform_int(rand_bytes_fn, n):
    # 返回 0..n-1
    limit = (256 // n) * n
    while True:
        b = rand_bytes_fn(1)[0]
        if b < limit:
            return b % n
```

多字节范围使用足够字节宽度并拒绝采样；禁止直接取模导致偏差。

### 2.8 六爻铜钱编码 `LIUYAO-COIN-001`

每爻三枚公平铜钱，正面=1，反面=0：

```text
k = b1 + b2 + b3
yao_value = 6 + k
```

| k | yao_value | 名称 | 动静 | 理论概率 |
|---:|---:|---|---|---:|
| 0 | 6 | 老阴 | 变 | 1/8 |
| 1 | 7 | 少阳 | 静 | 3/8 |
| 2 | 8 | 少阴 | 静 | 3/8 |
| 3 | 9 | 老阳 | 变 | 1/8 |

固定模式：`b_i` 由 `sub_seed("LIUYAO","yao_n","coin_i")` 派生。摇卦模式：`b_i` 来自系统安全随机源并写入快照。

### 2.9 隐私与日志 `SEED-PRIV-001`

日志不得记录：生辰原始值、生辰派生值、问事原文、HMAC 密钥。  
日志可记录：`bazi_present` 布尔、`question_hmac`（若用户选择关联）、`snapshot_digest`、`rng_version`。

## 3. 梅花易数引擎 `MEIHUA`

### 3.1 输入模型

| 字段 | 九色模式 | 传统数字模式 |
|---|---|---|
| `color_scheme` | `NINE_COLOR` | `TRADITIONAL_NUMBER` |
| `C` | `color_id ∈ 1..9` | 不使用 |
| `A` | `aux_id ∈ 1..12` | 不使用 |
| `U0,D0` | 不使用 | 两个正整数 |
| `Q` | 可选扰动，默认 0 | 默认 0；增强时启用 |
| `B` | 可选扰动，默认 0 | 默认 0；增强时启用 |
| `month_branch` | 用于旺衰 | 用于旺衰 |

Q/B 扰动为 L3 自定义增强，不启用时 `Q_mod=0, B_mod=0`。

> **校核状态：** 3.2–3.6 的起卦/互卦/变卦/体用五条规则已于 2026-11-06 按 `MEIHUA-CORE-v0.2` 完成校核（ADR-021）：17 个金标准案例、64 卦 × 6 动爻独立复算、双模式等价与 Q/B 扰动覆盖；规则与出处升为 `VERIFIED`。`VERIFIED` 不改变规则层级，九色参与起卦与 Q/B 扰动仍为 L3，规则集整体仍未冻结。

### 3.2 九色起卦 `MEIHUA-QIGUA-001`

```text
U_num = C mod 8; if U_num == 0: U_num = 8
D_num = A mod 8; if D_num == 0: D_num = 8
UPPER = trigram(U_num)
LOWER = trigram(D_num)

Q_mod = 0 或 int(question_hmac[0:16],16) mod 64
B_mod = 0 或 int(bazi_material_hash[0:16],16) mod 64

total = C + A + Q_mod + B_mod
M = total mod 6; if M == 0: M = 6
```

Q/B 仅在用户显式启用时计算：`Q` 材料为问事 HMAC（64 位十六进制）前 16 位，`B` 材料为生辰材料内存摘要前 16 位。材料缺失或格式非法时必须报错，不得静默回退为 0；问事历史关联开关与 Q 扰动开关相互独立（ADR-005）。

本卦为上 UPPER、下 LOWER；M 为动爻，初爻=1。

**规则层级：** 数字取模映射 L2；九色参与起卦 L3；Q/B 扰动 L3；不得将整个公式归为 L1 传统规则。

### 3.3 传统数字起卦 `MEIHUA-QIGUA-002`

```text
U_num = U0 mod 8; if U_num == 0: U_num = 8
D_num = D0 mod 8; if D_num == 0: D_num = 8
M = (U0 + D0) mod 6; if M == 0: M = 6
```

默认不使用 Q/B；用户显式启用增强时，按 L3 追加扰动并标注（ADR-005）：

```text
U_num = (U0 + Q_mod) mod 8; if U_num == 0: U_num = 8
D_num = (D0 + B_mod) mod 8; if D_num == 0: D_num = 8
M = (U0 + D0 + Q_mod + B_mod) mod 6; if M == 0: M = 6
```

未启用时 `Q_mod=B_mod=0`，两式退化为默认公式。该模式用于学习对照。

### 3.4 互卦 `MEIHUA-HUGUA-001`

本卦 binary 自下而上 `lines[0..5]`：

```text
lower_hu = lines[1:4]   # 二三四爻
upper_hu = lines[2:5]   # 三四五爻
HU = (upper_hu, lower_hu)
```

默认取本卦中间四爻。乾坤特殊规则作为可选配置 `hugua_special=false` 默认关闭；启用时按变卦取互，日志标注。

### 3.5 变卦 `MEIHUA-BIANGUA-001`


### 3.8 忌神与弱势卦位 `MEIHUA-JISHEN-001`（L3）

## 6. 择吉规则引擎 `ZEJI`

### 6.1 三层模型

1. **基础历法层：** 干支、节气月建、日支、生肖冲合、时区、日界，由 CAL v0.2 提供。

### 6.2 建除 `ZEJI-JIANCHU-001`

```text
idx = (day_branch_id - month_branch_id + 12) mod 12
jianchu = JC_ORDER[idx]
```

样例：月建寅(3)，日支午(7) → `(7-3+12) mod 12 = 4 → 定`。日支申(9) → `6 → 破`。

### 6.3 绝对过滤 `ZEJI-FILTER-001`（待冻结）

月破、岁破、四废、大耗的精确定义须配置化并冻结。过滤原因写入日志，不得静默过滤。

### 6.4 评分与冲突 `ZEJI-SCORE-001`

```text
for each rule in matched_rules:
    if result_type == ABSOLUTE_FILTER: mark filtered
    elif result_type == POSITIVE: add weight
    elif result_type == NEGATIVE: subtract weight
    elif result_type == CONFLICT: keep for explanation
```

输出保留：规则命中、过滤原因、加减分依据、事项适配、冲突解释。**不输出单一“吉日总分”作为唯一结论。** 不同事项使用不同规则集，不用同一套权重覆盖所有事项。
